# 管理界面第十轮多角度复验与优化方案（2026-09-03）

## 复验角度

前九轮已经为项目设置、组织项目、账号授权、执行监控、任务组、成员管理和智能体运行等页面补齐总览或操作看板。本轮继续从系统管理员的中文管理路径推演，重点检查“系统管理 → 组织管理”页是否仍然存在“总览有数字，但没有可点击操作入口”的问题。

复验角度包括：

- 系统管理员路径：进入组织管理页时，常见动作是先看组织启停状态、配额压力和风险组织，再决定调整配额、停用/启用组织或创建新组织。
- 中文后台习惯：系统级资源边界页应遵循“总览 → 操作看板 → 现状列表 → 创建表单 → 说明”，避免管理员还没核对组织现状就进入创建组织。
- 图形化入口：组织管理总览已有组织总数、启用中、停用/异常、配额接近上限，但这些只是指标，不是可点击入口。
- 操作闭环：组织列表、配额调整、启停组织、创建组织属于同一条系统管理链路，应在总览后形成可跳转入口。
- 信息完整性：不减少组织列表、配额调整、启停组织、创建组织、职责边界说明和现有指标。
- 性能边界：只用当前已加载的组织数据聚合，不新增接口、不增加轮询、不引入依赖；继续复用 `jumpModuleCard` 与 `data-jump-panel`。

## 发现的问题

- 「系统管理 → 组织管理」页当前顺序是“组织管理总览 → 组织列表 → 创建组织 → 说明”。顺序基本正确，但缺少总览后的图形化操作入口。
- 用户看到“配额接近上限 1”“停用 / 异常 1”后，不能直接跳到组织列表处理，只能继续向下读长表。
- 创建组织会改变系统资源边界，应当放在管理员核对组织状态和配额压力之后；页面需要更明确表达这个处理顺序。
- 与账号授权、组织项目、项目设置和执行监控页相比，系统组织页缺少同形的入口地图，后台整体交互一致性不足。

## 优化方案

- 新增“组织与配额操作看板”，放在“组织管理总览”之后、“组织列表”之前。
- 看板卡片覆盖：启用组织、停用/异常、配额压力、组织总数、创建组织、治理说明。
- 启用组织、停用/异常、配额压力和组织总数卡片跳转到“组织列表”；创建组织卡片跳转到“创建组织”；治理说明卡片跳转到“说明”。
- 看板说明固定处理顺序：先核对组织状态、配额压力和启停风险，再创建组织或调整配额。
- 补充行为门，断言系统组织页必须先显示总览和操作看板，再显示组织列表、创建组织和说明，并断言看板跳转目标存在。

## 验收要求

- 桌面页面：系统组织页先显示组织管理总览、组织与配额操作看板，再显示组织列表、创建组织和说明。
- 移动端页面：390px 宽度下新增操作看板不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录系统组织页，检查看板可读性、卡片跳转和窄屏表现。

## 实施结果

- 已在 `apps/control-plane-ui/public/app.js` 新增“组织与配额操作看板”，放在“组织管理总览”之后、“组织列表”之前。
- 看板复用现有 `jumpModuleCard`，不新增接口、不新增轮询、不新增依赖；所有指标均来自当前已加载组织列表。
- 已补充 `scripts/console-behaviour-check.mjs` 行为门，覆盖系统组织页的面板顺序和看板跳转目标。
- 已通过 `node --check apps/control-plane-ui/public/app.js`、`node --check scripts/console-behaviour-check.mjs`、`git diff --check`、`npm run -s console-behaviour-gate`、`npm run -s mutation-anchors`。
- 真实浏览器桌面走查通过：系统组织页显示 5 个面板，顺序为“组织管理总览 → 组织与配额操作看板 → 组织列表 → 创建组织 → 说明”；看板 6 张卡片均有明确跳转目标；页面无横向溢出。
- 真实浏览器交互走查通过：点击“组织列表”和“创建组织”卡片后，对应面板进入当前视口。
- 真实浏览器 390px 窄屏走查通过：看板仍为 6 张可读卡片，页面级 `scrollWidth` 与视口宽度一致；组织表保持表格内部横向滚动，不撑开整页。
