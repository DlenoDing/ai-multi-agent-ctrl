# 管理界面第八轮多角度复验与优化方案（2026-09-03）

## 复验角度

前七轮已经把系统管理、组织管理、项目管理拆成独立空间，并为账号授权、执行监控、人工处置、项目概览等页面补了总览或操作看板。本轮继续按普通中文用户的真实管理路径推演，重点检查“项目设置”这种高密度页面是否仍然存在入口不清、配置块混在一起、用户需要先读完整页才知道从哪里下手的问题。

复验角度包括：

- 项目管理路径：项目负责人进入项目设置时，通常先判断“产出落哪里、agent 怎么接入、规则是否可用、默认角色是否齐全”，再编辑具体字段。
- 中文阅读习惯：中文后台管理更适合“总览 → 操作看板 → 明细配置”的顺序，而不是直接把长表单推到用户面前。
- 图形化入口：项目设置页已有指标，但指标不可点击；用户看到“仓库 1、规则 32、令牌 0”后不能直接跳到对应配置区。
- 操作闭环：agent 入网、规则维护、仓库落点、默认角色都是执行链路的前置条件，应当在同一页形成可跳转的检查清单。
- 信息完整性：不减少仓库、基线、默认角色、智能体入网、系统规则、业务规则等现有功能。
- 性能边界：只使用当前页已经加载的数据聚合，不新增接口、不增加轮询、不引入依赖；卡片跳转使用已有 `data-jump-panel` 机制。

## 发现的问题

- 「项目设置」页当前顺序是“项目设置总览 → 项目设置长表单 → 智能体接入 → 系统规则 → 业务规则”。总览能看到数量，但不能作为入口使用。
- “项目设置 · 项目名”这个面板同时承载仓库、基线数据、默认角色三类配置。标题没有表达这三类配置共同影响的是“基础执行配置”，普通用户不容易把它和 agent 产出落地、派发角色回退联系起来。
- 用户如果只想处理 agent 入网或规则配置，需要向下滚动寻找；对窄屏和数据较多的项目尤其不清晰。
- 项目设置页缺少一张面向执行准备度的图形化操作看板，不能像项目概览、执行监控、账号授权页一样先给清晰入口，再给详细表单。

## 优化方案

- 新增“项目设置操作看板”，放在“项目设置总览”之后。
- 看板卡片覆盖：产出仓库、基线数据、默认角色、智能体入网、系统规则、业务规则。
- 看板卡片直接跳转到对应面板：产出仓库、基线数据、默认角色跳到“项目基础配置”；智能体入网跳到“智能体接入”；系统规则和业务规则跳到各自面板。
- 将“项目设置 · 项目名”面板改名为“项目基础配置”，项目名称在面板说明中保留，降低标题噪音，让用户先按配置类别理解页面。
- 补充行为门，断言项目设置页必须先显示总览和操作看板，再显示基础配置、智能体接入和规则面板；并断言操作看板卡片具备跳转目标。

## 验收要求

- 桌面页面：项目设置页先显示总览、操作看板，再显示基础配置、智能体接入、系统规则和业务规则。
- 移动端页面：390px 宽度下新增操作看板不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录项目设置页，检查看板可读性、卡片跳转和窄屏表现。

## 实施结果

- 已新增“项目设置操作看板”，覆盖产出仓库、基线数据、默认角色、智能体入网、系统规则和业务规则。
- 已复用既有 `jumpModuleCard` 与 `data-jump-panel` 跳转机制，不新增接口、不新增轮询、不引入依赖。
- 已将项目设置页顺序调整为“项目设置总览 → 项目设置操作看板 → 项目基础配置 → 智能体接入 → 系统规则 → 业务规则”。
- 已将原“项目设置 · 项目名”面板改为“项目基础配置”，并在面板内说明当前项目名称和该区域的配置目的。
- 已补充行为门断言，确保项目设置页先显示总览和操作看板，再进入基础配置、入网和规则明细，并确保看板卡片带有基础配置、智能体接入、系统规则、业务规则跳转目标。
- 已完成快速工程验证：语法检查、diff 卫生、console-behaviour-gate 和 mutation-anchors 通过。
- 已完成真实浏览器桌面复验：项目设置页展示 6 个入口卡片，面板顺序为“项目设置总览 → 项目设置操作看板 → 项目基础配置 → 智能体接入 → 系统规则 → 业务规则”，页面级横向溢出为 false。
- 已完成真实浏览器交互复验：点击“系统规则”操作卡片后，页面能直接滚动定位到“系统规则”，目标标题处于可视区域。
- 已完成真实浏览器窄屏复验：390px 宽度下操作看板保留 6 个入口卡片，面板顺序保持不变，页面级横向溢出为 false。
