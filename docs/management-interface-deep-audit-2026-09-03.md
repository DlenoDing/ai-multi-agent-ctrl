# 管理界面深度复验与优化方案（2026-09-03）

## 复验范围

本轮复验覆盖 AI Multi-Agent Ctrl 控制台的系统管理、组织管理、项目管理三个管理空间，以及任务组、审核、指令、监控、项目设置等项目内模块。复验同时查看源码结构、已有契约门、真实本地页面、桌面与移动端布局。

## 第一轮：功能层级与空间边界

已完成的系统/项目分离解决了左侧菜单混排问题，但系统概览和组织概览仍主要是指标、说明、表格堆叠。项目概览已有图形化模块枢纽，系统与组织首页没有同等入口，普通用户进入系统管理后需要从多个面板里读出下一步。

优化方向：
- 系统概览增加“系统管理总览”，用健康环和模块卡表达组织、账号授权、模型技能源、项目空间入口。
- 组织概览增加“组织管理总览”，用在线节点/组织状态和模块卡表达成员、智能体、项目列表、项目空间入口。
- 保留现有明细面板，不删减运维数据、审计、配额、项目列表等信息。

## 第二轮：中文管理路径

上一轮复验时，项目空间仍存在直接指向“AI 智能体页”的提示。分离后，系统管理员在项目空间看不到该页；组织管理员也需要先切回组织管理空间。直接写页名会造成“照着提示找不到入口”。

优化方向：
- 项目空间内的跨空间提示统一改成“先切到某管理空间，再打开某功能”。
- 已补充项目级“AI 智能体”入口：有项目 `agent:activate` 权限的账号在「项目管理」→「AI 智能体」→「注册 agent」签发入网令牌；节点状态与自检异常仍由组织管理员在「组织管理」→「AI 智能体」处理。
- 普通成员不显示自己无法执行的后台路径，提示联系组织管理员。

## 第三轮：信息密度与视觉层级

当前详情页保留了大量必要信息，但首页需要先回答“这里管什么、下一步去哪、哪些状态异常”。纯表格适合查明细，不适合作为管理入口。

优化方向：
- 首页使用模块卡承载常用路径，数字作为首要视觉信号，说明文字作为辅助。
- 明细表继续放在模块卡之后，用于追查和审计。
- 卡片颜色只表达状态强弱，不引入新的业务含义。

## 第四轮：移动端和窄屏

上一轮已修正项目枢纽 390px 被压窄的问题。本轮新增系统/组织枢纽后，必须复用同一响应式规则，避免桌面可读但移动端挤压。

验收要求：
- 390px 宽度下系统、组织、项目首页模块卡无横向溢出。
- 顶部空间切换与左侧横向菜单可见、可滚动、不中断操作。
- 浏览器控制台无前端错误。

## 第五轮：稳定性和性能

本轮优化只使用当前视图已下发的数据做聚合，不新增接口，不扩大状态视图，不读取技能正文等大字段。所有新增入口都走已有 `data-menu` 导航，继续复用原页面加载、权限、实时刷新与待办计数逻辑。

验收门：
- 语法检查与 diff 卫生通过。
- `console-behaviour-gate`、`contract:check`、`validate`、`docker:doctor` 通过。
- 本地浏览器完成系统/组织/项目首页桌面与 390px 移动端走查。
