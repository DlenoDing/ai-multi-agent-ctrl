# 管理控制台从属层级收敛方案

日期：2026-09-07  
状态：已完成并通过终态复验

## 问题结论

当前系统的数据权限和作用域已经区分系统、组织、项目、任务组、任务和执行对象，但界面名称与跳转方式没有完全表达这套层级：

- 项目设置和任务组详情同时出现“默认角色、Skill 定制、系统规则、业务规则”，标题没有说清是项目默认值还是任务组覆盖。
- 项目级人工审核、人工指令与任务组级审核、指令共享同一组入口，用户依赖跳转后的标题才能确认作用域。
- 任务详情先展示全部执行尝试，最后才展示结果；执行次数较多时，人无法快速知道最终产出。
- 每次执行同时提供“查看本次执行、历史执行记录、本次执行规则”三个入口，分别切到不同状态或页面，形成交叉导航。
- 项目概览、任务组详情、任务详情和执行监控都提供跨模块按钮，部分按钮只写“查看／前往”，无法预判点击后的落点。

本轮不删除 Agent、角色、规则、审核、指令、实时监控、Git 证据或对象详情，只调整所属位置、显示名称和入口数量。

## 权威从属层级

```text
组织
└─ 项目
   ├─ 项目资源
   │  ├─ 项目成员
   │  ├─ 项目 Agent 档案
   │  └─ 项目运行节点
   ├─ 项目默认配置
   │  ├─ 仓库与基线
   │  ├─ 默认角色与 Skill
   │  └─ 默认系统规则与默认业务规则
   ├─ 任务组
   │  ├─ 任务组角色
   │  ├─ 项目默认值继承
   │  ├─ 任务组 Skill 覆盖
   │  ├─ 任务组规则覆盖
   │  ├─ 任务组监控
   │  ├─ 任务组人工审核
   │  └─ 任务组人工指令
   └─ 任务
      ├─ 当前执行结果
      ├─ 执行要求
      ├─ 执行尝试
      └─ 单次执行详情
         ├─ Agent / 角色 / 模型 / Skill / 规则
         ├─ 实时事件
         ├─ 控制命令
         └─ Git 检查点与质量证据
```

## 界面规则

### 项目层

- 侧栏使用“成员与 Agent”“项目默认配置”“人工审核与指令”等明确对象名称。
- 项目默认配置的叶子名称必须带“项目”或“默认”，避免和任务组覆盖同名。
- 项目级审核与指令页是跨任务组汇总入口；进入具体任务组后继续沿用当前任务组作用域。

### 任务组层

- 任务组详情内部只管理当前任务组，不再使用看不出层级的“配置继承／Skill 定制／系统规则／业务规则”。
- 对应名称收敛为“项目默认值、任务组 Skill、任务组系统规则、任务组业务规则”。
- 角色栏目表达本组实际参与角色；项目 Agent 页面只表达可调配执行资源，两者不得混为一个对象。

### 任务层

- 任务标题和状态之后立即显示“当前执行结果”，先回答做成了什么、落在哪个仓库、是否提交和推送。
- 结果至少显示仓库、分支、实际提交、推送状态、产出清单和最近更新时间；没有结果时明确说明当前处于什么阶段。
- 执行要求位于结果之后；执行尝试位于要求之后。
- 每次执行只保留一个“查看执行详情”入口。事件、规则、模型、Agent、节点和证据均在统一执行对象详情中查看，不再从同一行跳到三个栏目。

### 跳转规则

- 列表进入详情；详情返回直属上级；项目汇总只在确有待办时提供一个明确下一步。
- 状态摘要默认不作为导航；确需跳转的按钮必须在可见文案中说明目标。
- 当前任务组作用域在任务、监控、审核和指令之间保持，不允许点击普通入口后静默退回整个项目。
- 浏览器前进、后退和深链接继续使用现有稳定对象地址。

## 实施结果

- 项目侧栏收敛为“日常工作、成员与 Agent、执行监控、验收与收口、人工审核与指令、项目默认配置”。项目默认配置内明确使用项目仓库、项目基线、项目默认角色、项目默认 Skill、项目系统规则和项目业务规则。
- 任务组对象栏收敛为“工作推进、任务组配置、执行与审计”。配置项明确使用任务组角色、继承与覆盖、任务组 Skill、任务组系统规则和任务组业务规则。
- 当前任务组快捷入口统一标成“本组任务、本组监控、本组审核、本组指令”，不再让用户猜测项目汇总与任务组作用域。
- 任务详情将当前执行结果移到执行要求和执行过程之前，完整显示仓库、分支、提交、推送、变更文件、产出清单、检查点和更新时间。
- 任务列表直接显示结果已推送、结果已提交、产出生成中、暂无执行结果或未记录结果；已验证但没有任何结果证据的任务会明确标红。
- 最新一次执行固定显示在前，较早且已结束的执行折叠保留；单次执行只保留一个“查看执行详情”入口。
- 项目概览资源数字和关键指标恢复为只读事实，任务组表删除重复“操作／进入任务组”列；主内容按钮由 18 个降至 10 个。
- 真实种子任务含 7 次执行时，桌面任务详情由 1983px 降至 1487px，390px 由 2856px 降至 2035px；完整历史仍可展开。

## 外部复审

- Claude Sonnet/medium 对数据形态、继承语义、结果误报、历史折叠、导航可达性和转义安全执行只读复审，未发现阻塞问题。
- 复审确认字符串与对象两类提交／推送引用均正确解析，推送状态由证据驱动，较早执行不会丢失，移除的概览按钮均有正规侧栏或对象入口。
- 复审指出“项目默认值”不能准确表达任务组定制状态，最终名称已修正为“继承与覆盖”。

## 验收标准

- 用户只看名称即可区分项目默认配置、任务组覆盖和单次执行实际采用值。
- 打开任务详情后无需滚过执行历史即可看到当前结果和 Git 落点。
- 每次执行只有一个详情入口，不再在任务页内形成三条交叉跳转路径。
- 项目、任务组、任务、执行对象的返回关系和作用域稳定。
- 1440px 与 390px 无重叠、页面级横向溢出或关键结果被折叠隐藏。
- 服务端权限、状态机、实时回送、集中式 MCP、Skill 同步和 Git 写入契约不变。
