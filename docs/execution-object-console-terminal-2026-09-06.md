# 执行对象管理控制台终态补全

日期：2026-09-06  
状态：已完成

## 本轮结论

系统、组织和项目管理空间已经分开，组织子账户及项目／任务组授权、组织共享 Agent 与项目 Agent、项目仓库凭据、任务组和任务详情也已有真实服务端能力。当前最影响普通管理者认知的剩余问题不再是“缺一张统计卡”，而是执行域仍以页面栏目和表格为中心：工作会话、Agent 派发与运行节点还不是可独立进入、可复制地址、可持续回看的管理对象。

上一份对象中心文档把“会话与派发是可直接进入的对象”列为目标并在验收语义中视为已完成，但实际代码只有“事件”按钮：点击后把监控页切到实时事件栏目，并未提供会话或派发详情。该结论在本轮纠正，不再以栏目筛选等同于对象管理。

## 已确认边界

1. **系统管理**只负责平台运行、组织开通、初始组织管理员、组织启停和配额，不把组织子账户、项目执行和 Agent 日常治理重新放回系统空间。
2. **组织管理**负责组织成员、项目／任务组授权、组织级 Agent 档案和共享运行节点；项目成员和任务组权限仍由组织管理员或项目授权者按对象分配。
3. **项目管理**负责当前项目、成员、项目 Agent、任务组、任务、执行监控、人工审核、独立指令、仓库和规则。人只做治理、入口控制与必要审核，任务拆解、Agent／模型／Skill 选择、调度、执行和过程回送仍由 AI 总控自动完成。
4. 组织级 Agent 档案和共享节点可供组织内项目调配；项目级 Agent 档案和项目节点只服务绑定项目。档案描述逻辑执行身份，节点描述实际运行载体，两者不能混成同一对象。
5. 项目、任务组和任务进度继续由服务端事实计算；界面只展示和导航，不新增一套客户端进度状态。

## 当前缺口

### P1：工作会话和 Agent 派发不是真正对象

- `renderMonitor()` 只把会话和派发渲染成表格行，详情按钮实际叫“事件”。
- `show-session-events` 和 `show-dispatch-events` 只修改 `execScope` 并切到监控事件栏目。
- URL 只保存项目、任务组和栏目，不保存会话／派发对象；刷新、复制地址或浏览器返回无法恢复同一执行对象。
- 主状态视图对账本有窗口上限，旧会话／派发即使仍可按权限读取，也可能因未出现在当前窗口而被界面视为不存在。

### P1：任务执行次数无法连续追查

任务详情能够看到每次派发的摘要、规则和事件，但进入监控后丢失“这是哪一次执行”的对象头。反向从监控表格也不能直接返回所属任务。Agent 档案、运行节点、角色、实际模型、推理级别、Skill、契约、控制命令、事件和仓库证据被拆散在不同面板，排障需要人工抄 ID 搜索。

### P1：项目监控与任务组监控名称和上下文不够明确

同一个 `renderMonitor()` 同时承载项目和任务组范围，页头始终叫“执行监控”。范围下拉能过滤数据，但没有把“项目执行总览”与“任务组控制室”明确表现成不同对象上下文；任务组审核者进入后仍先看到通用项目级栏目结构。

### P2：监控首页信息密度过高

监控首页同时输出总览、处置看板、实时链路、任务组矩阵和自治控制。它们都有效，但入口层级重复。普通管理者需要的是当前范围、是否异常、下一处置对象和最近运行；协议说明与完整证据应在对象详情或按需栏目中展开。

### P2：执行域继续堆入主文件

`app.js` 仍有 10,591 行，`renderMonitor()` 单函数负责作用域、数据聚合、所有表格和人工处置。继续直接添加详情会扩大主文件和回归面。本轮新增执行对象展示、归属解析和详情布局必须进入独立模块；主文件只保留状态装配、读取和事件路由。

### P2：窄屏上的对象返回链尚未覆盖执行对象

任务和 Agent 档案已有对象头与返回入口，但会话／派发只能回到通用监控。390px 下必须持续显示对象名称、状态、进度、所属任务组／任务和唯一主要操作，不能依赖横向表格找到上下文。

## 终态方案

### 1. 服务端执行对象详情

新增按对象读取的只读接口：

```text
GET /api/work-sessions/:sessionId/detail
GET /api/agent-dispatches/:dispatchId/detail
```

接口必须重新鉴权所属任务组，并返回当前对象、关联会话／派发、任务组摘要、任务、Agent 档案公开字段、运行节点公开字段、模型选择、会话放置、控制命令和规则契约摘要。事件仍走现有可长轮询的专用事件接口，避免详情响应随事件量无界增长。

### 2. 可寻址执行对象

```text
#/project/<projectId>/monitor/<taskGroupId>/session/<sessionId>
#/project/<projectId>/monitor/<taskGroupId>/dispatch/<dispatchId>
```

地址只含安全对象 ID，不含令牌、任务正文、规则正文或结果。直接打开、刷新和浏览器前进／后退均须重新从服务端鉴权；对象不存在、跨项目或无权限时回到所属可见监控范围并明确提示。

### 3. 执行对象工作区

会话和派发详情采用相同的对象工作区骨架：

- 对象头：类型、ID、状态、进度、最近活动、所属任务组和任务。
- 执行身份：逻辑 Agent、运行节点、角色、组织／项目作用域。
- 调度决定：实际模型、推理等级、一行 `modelDecision`、会话放置和执行载体。
- Skill 与规则：角色 Skill、工作集、规则集摘要、禁止动作、验收要求；长正文不重复下发。
- 实时过程：最新／历史事件切换、事件时间线、控制命令及 ACK。
- 结果证据：仓库目标、提交、推送、检查点、质量门和失败原因。
- 控制：只有具备该任务组权限且对象可控时才显示暂停、恢复或取消；所有动作继续走服务端状态机。

从任务详情、会话表和派发表进入的都是同一个工作区，不生成三套详情实现。

### 4. 明确监控范围

- 未选任务组时显示“项目执行总览”，重点展示任务组矩阵、异常数、活跃会话／派发和最近事件。
- 选定任务组时显示“任务组执行监控”，对象头持续显示该组进度、运行、待审和阻塞数，并可直达任务、审核、指令。
- 会话／派发详情打开后隐藏移动端栏目选择器和通用监控标题，避免“对象详情嵌在另一个 Tab”视觉。

### 5. 性能与稳定性

- 详情接口只做一次对象索引和受限关联，不下发完整项目状态或无限事件。
- 客户端只在打开执行对象时读取详情；监控列表仍使用已有有界视图。
- WebSocket 只发唤醒信号，刷新详情和事件时继续走鉴权接口；后台刷新不得覆盖未保存表单。
- 新模块保持无框架、无额外运行依赖，复用现有 HTML 转义、状态徽标和权限判定。

## 实现结果

- 工作会话和 Agent 派发新增按所属任务组重新鉴权的详情 API，并由 `execution-object-detail/v1` Schema 约束。详情响应只带有界关联数据；执行事件继续走原有游标／长轮询接口。
- 运行节点新增组织／项目两种详情投影和 `runtime-node-detail/v1` Schema。项目投影只返回当前项目的派发、控制命令、事件、逻辑 Agent 档案与节点能力；普通账号不能枚举其它租户节点，系统账号对不存在或不属于目标项目的对象得到明确 404。
- 新增会话、派发和运行节点独立地址。直接登录、刷新、浏览器前进／后退和窗口外对象恢复都重新读取服务端并鉴权；路由只保存白名单 ID，不保存令牌、正文或结果。
- 任务执行次数、监控会话表、监控派发表和节点当前负载统一进入同一个派发对象工作区。对象关系按“任务组 → 任务 → 会话 → 派发 → 运行节点”展示，不需要复制 ID 到其它表格搜索。
- 派发／会话详情集中展示 Agent 档案及作用域、角色、实际模型、中文推理档、`modelDecision`、会话放置、执行载体、真实 `roleSkillRef`、生效规则、控制命令 ACK、实时／历史事件、仓库目标、检查点和质量证据。
- 节点详情集中展示心跳与自检、Runtime 版本、调配项目、角色、远程 MCP 工具、主机模型与工具、匹配 Agent 档案、活动派发、控制命令和近期事件。心跳超时从当前时间派生，不再照抄持久状态里的“在线”。长 MCP 工具清单默认折叠，信息保留但不挤占首屏。
- 项目监控和任务组监控有独立对象头。任务组范围固定显示进度、任务、活跃会话、派发、待审核和受阻数，并可返回项目监控或进入任务组详情。
- 高影响的暂停、恢复和取消从派发表格收进具体派发详情，只在当前任务组有控制权时出现且明确绑定派发 ID；只读观察者可追踪完整执行链，但不获得任何控制按钮。
- 登录后直接打开派发／会话深链接时，会等待首批事件加载后再呈现，避免服务端已有事件而页面短暂显示“没有过程事件”。
- 系统层遗留 `sys-accounts` 混合页面及账号邀请、通用授权、系统级项目创建和 Agent 档案表单已删除。组织成员、项目／任务组授权、Agent 档案分别只保留在组织或项目对象内。
