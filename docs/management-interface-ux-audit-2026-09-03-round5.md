# 管理界面第五轮多角度复验与优化方案（2026-09-03）

## 复验角度

本轮继续从普通中文管理者的阅读顺序推演项目内人机控制链路。前三轮和第四轮已经把系统/组织/项目的大入口与高密度配置页补上总览，本轮重点检查“人需要介入 AI-native 系统时”能不能先看懂状态，再做决定。

复验角度包括：

- 人机控制闭环：人工审核、人工指令不能只展示表单和记录，应先说明当前待办、风险与操作入口。
- 操作先后顺序：人下指令前应先看到历史指令、待处理指令与拒绝原因，避免重复下达或误判系统没接收。
- 风险可见性：待确认、授权请求、审批请求、发现项、已答历史和定稿记录应有页面级汇总。
- 信息完整性：原有表单、长表、审计和处置动作全部保留，只在上层增加状态地图或调整顺序。
- 性能边界：新增总览只聚合当前页面已经加载的数据，不新增接口、不新增后台轮询。

## 发现的问题

- 「人工审核」页虽然已有“待你处理”汇总，但页面缺少项目范围的审核总览。用户需要读完“待人工确认 / 授权与处置 / 已答历史”三个面板，才知道当前阻塞集中在确认、授权、审批、发现还是历史定稿。
- 「人工指令」页首屏先出现“下达人工指令”表单，再出现“指令流水”。这会鼓励用户先操作，而不是先看已有指令是否已提交、是否被拒、是否仍待执行。
- 指令页缺少状态总览，用户不能快速判断当前项目有多少人工指令、多少还在待处理、多少已执行、多少被拒绝、覆盖了几个任务组。

## 优化方案

- 新增“人工审核总览”：展示待人工确认、授权请求、审批请求、待处置发现、已答历史、最近定稿，并给出查看顺序。
- 新增“人工指令总览”：展示指令总数、待处理、已执行、已拒绝、涉及任务组、可控任务组，并说明人工指令是结构化输入，不直接改总控会话。
- 调整「人工指令」页顺序为“人工指令总览 → 指令流水 → 下达人工指令”，让用户先看历史和状态，再决定是否下发。
- 补充行为门，断言人工审核页必须先出现审核总览，人工指令页必须先出现指令总览和流水，再出现下达表单。

## 验收要求

- 桌面页面：人工审核页首屏先出现“人工审核总览”；人工指令页先出现“人工指令总览”和“指令流水”，再出现“下达人工指令”。
- 移动端页面：390px 宽度下新增总览不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、contract:check、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录项目管理页，检查人工审核和人工指令的首屏顺序与可读性。

## 实施结果

- 已新增“人工审核总览”，在项目范围内先聚合待人工确认、核心决策、授权请求、审批请求、待处置发现、涉及任务组、已答历史和最近定稿。
- 已将“最近的人工定稿”计算抽成统一 helper，人工审核页和执行监控页共用同一口径，避免重复实现漂移。
- 已新增“人工指令总览”，并把人工指令页顺序调整为“总览 → 指令流水 → 下达人工指令”。
- 已补充行为门断言，确保人工审核页和人工指令页后续不会退回到先显示长表或表单的结构。
- 已完成快速工程验证：语法检查、diff 卫生、console-behaviour-gate 和 mutation-anchors 通过。
- 已完成真实浏览器桌面走查：人工审核页面板顺序为“人工审核总览 → 待你处理 → 待人工确认 → 授权与处置 → 已答历史”；人工指令页顺序为“人工指令总览 → 指令流水 → 下达人工指令”。
- 已完成 390px 窄屏走查：人工审核页和人工指令页无页面级横向溢出；项目导航仍按既有横向滚动处理。
