# 管理界面第二十三轮复验与优化方案

## 复验范围

- 项目管理主线：项目概览、AI 智能体、任务组、执行监控、人工审核、人工指令、项目设置。
- 任务组执行主线：总控拆解、角色列表、继承配置、执行控制、工作项、关闭门禁、协作记录。
- 中文用户阅读习惯：先看概览和处置入口，再进入明细；先判断状态，再操作；高密度内容必须有分区路径。
- 性能边界：只复用当前已加载的任务组详情数据，不新增接口、不增加轮询、不引入依赖。

## 当前结论

前二十二轮已经把系统管理和项目管理边界、项目 Agent 注册入口、注册脚本说明、项目概览操作路径、智能体卡片视图等关键问题补齐。继续推演后，任务组详情仍存在一个影响普通用户阅读和管理的结构性问题：展开某个任务组后，事项清单、角色、配置、执行控制、工作项、准入阻断、阻塞、协作记录直接纵向堆叠。功能信息没有丢，但用户必须顺序阅读很长的内容才能知道下一步该看哪里、管哪里。

## 问题清单

1. 任务组详情缺少“展开后先看什么”的图形化路径。
2. 详情内已有多个小节，但现有 `data-jump-panel` 只能跳转到顶层 panel，不能跳到详情小节。
3. 工作项小节标题可能带真实总数和截断说明，跳转目标不能依赖完全固定标题。
4. 如果继续只增加文字说明，会再次变成内容堆砌；应复用现有模块卡片样式，保持首屏可扫读。

## 优化方案

1. 在任务组详情顶部新增“任务组详情阅读路径”小节，用图形化卡片按自然阅读顺序组织八个入口：事项清单、角色列表、配置、执行控制、工作项、准入与阻断、阻塞、协作记录。
2. 每张卡片显示对应数量或状态，例如工作项数量、角色数、阻塞数、配置来源、控制权限，帮助用户先判断优先级。
3. 扩展小节渲染，让 `sectionBlock` 输出稳定的 `data-section-title`，并让跳转处理器先找顶层 panel，再找详情小节。
4. 对动态标题采用前缀匹配，例如卡片跳“工作项”时可命中“工作项（共 4000 个，当前展示 300 个）”。
5. 增加控制台行为门：验证阅读路径出现位置、八个跳转入口、详情小节锚点和跳转处理器的小节支持。
