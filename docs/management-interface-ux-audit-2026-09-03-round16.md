# 管理界面第十六轮多角度复验与优化方案（2026-09-03）

## 复验范围

第十四轮为侧栏菜单补充用途说明，第十五轮修正品牌区空间识别。本轮继续从桌面后台长时间管理、中文菜单扫读、移动端首屏和信息密度四个角度复验：菜单说明存在以后，侧栏是否仍适合普通中文用户快速阅读。

复验角度包括：

- 中文后台习惯：桌面后台左侧菜单通常承担模块目录职责，标题和说明需要有足够横向空间，不能因为过窄而变成密集文字块。
- 信息密度：系统、组织、项目三类空间共有 14 个页面，说明文字最长包含“组织内智能体节点”“仓库与凭证引用、基线数据”等中文长短语，224px 宽度会让说明过度换行。
- 功能完整性：不减少菜单说明、不隐藏待办徽标、不改变系统 / 组织 / 项目空间切换，只优化可读宽度和徽标稳定性。
- 移动端边界：移动端仍按 100% 宽度横向导航，不能把桌面侧栏宽度带到窄屏。
- 性能边界：纯 CSS 布局调整，不新增接口、不新增轮询、不引入依赖。

## 发现的问题

- 侧栏在桌面端固定为 224px。补充用途说明后，部分页面说明会换成 3 到 4 行，普通用户扫读时容易把多个入口读成一整块文字。
- 菜单待办徽标位于标题行右侧，但样式没有显式设置 `flex-shrink: 0`；在极端长标题或未来新增长标题时可能被压缩。
- 移动端已有 `.sidebar { width: 100%; flex: none; }`，可以安全地只调整桌面侧栏宽度，不影响窄屏。

## 优化方案

- 将桌面侧栏宽度从 224px 调整为 264px，让“标题 + 用途说明”的目录结构更接近中文管理后台常见宽度。
- 将侧栏 `flex-basis` 同步调整为 264px，避免布局声明不一致。
- 为 `.nav-badge` 增加 `flex: 0 0 auto`，保证待办计数在标题行稳定显示。
- 补充行为门，断言桌面侧栏宽度与 `flex-basis` 保持一致且不低于 256px，断言移动端仍覆盖为 100% 宽度，断言待办徽标不可收缩。

## 验收要求

- 桌面页面：侧栏菜单说明更易扫读，系统、组织、项目三类空间菜单仍完整显示。
- 移动端页面：390px 宽度下侧栏仍为 100%，菜单说明隐藏，页面级无横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录项目成员视角，检查桌面侧栏宽度、菜单说明可见、移动端无溢出。
