# 管理界面第三轮多角度复验与优化方案（2026-09-03）

## 复验范围

本轮在第二轮修正后重新从源码、真实本地页面、系统管理员视角、项目负责人视角、移动端视角和契约门视角复验。重点不是继续拆功能，而是检查普通中文用户打开页面后能否先看懂状态，再做操作；同时确保 AI-native 运行链路、实时监控、项目配置和账号授权等必要信息不被隐藏或删减。

## 发现的问题

- 账号与授权页首屏直接进入“邀请账号 / 新增访问授权 / 创建项目 / 项目成员授权”等表单。功能完整，但用户需要向下读完整页，才知道当前账号、授权、项目、加入令牌和 agent 档案的总体情况。
- 任务组页首屏先显示创建任务组和创建工作项表单，然后才是已有任务组。对管理者来说，最常见动作是先查看任务组状态，再决定是否创建或追加工作项。
- 执行监控页包含实时事件、执行载体、会话、派发、控制通道、节点、模型选择、放置、准入、检查点、关闭门禁等 13 个面板。信息完整，但缺少顶部“监控总览”，用户很难在第一屏判断当前到底是节点问题、派发问题、会话问题，还是关闭门禁问题。
- README 仍有一处“系统设置 → 模型能力注册”被包在同一组书名号内。运行界面已改成分级路径，文档也应一致。

## 优化方案

- 在「系统管理」→「账号与授权」页新增“账号与授权总览”，以指标块展示账号总数、启用账号、服务账号、有效授权、项目数、待用加入令牌、agent 档案和启用档案。原有表单与列表全部保留。
- 在「项目管理」→「任务组」页新增“任务组总览”，以指标块展示任务组总数、进行中任务组、平均进度、工作项、受阻项和统一语言分布。创建表单保留在总览之后，避免首屏直接进入操作表单。
- 在「项目管理」→「执行监控」页新增“执行监控总览”，以指标块展示实时事件、活跃会话、待执行派发、执行载体、在线节点和关闭阻塞，并给出查看顺序提示。
- 将 README 剩余路径改成分级书名号形式，保持文档、界面、契约门一致。

## 实施结果

- 已新增“账号与授权总览”，并在真实系统管理员页面验证它位于“邀请账号”等表单之前。
- 已新增“任务组总览”，并在真实项目页面验证它位于“创建任务组”“创建工作项”之前。
- 已新增“执行监控总览”，并在真实项目页面验证它位于自治控制、实时事件流和各类长表之前。
- 已补充行为门断言，确保三页后续不能退回到表单或长表直接开头。
- 已完成 390px 窄屏走查，新增总览不造成主体横向溢出；横向菜单和表格仍按既有滚动容器处理。

## 验收要求

- 桌面页面：账号与授权、任务组、执行监控首屏均先出现总览，再出现操作表单或明细表。
- 移动端页面：390px 宽度下新增总览无主体横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、contract:check、validate、docker:doctor 通过。
- 性能边界：所有总览只用当前视图已加载数据聚合，不新增接口、不扩大视图载荷、不新增持续轮询。
