# 管理界面与交互复验审计 Round 45

审计时间：2026-09-04 17:18 +08

- 重点检查项目管理侧栏是否符合普通中文用户“先准备、再执行、再人工控制、最后治理配置”的阅读和管理习惯。
- 继续核对 Agent 注册、注册脚本、远程 MCP/Skill、任务组、监控、审核、指令和项目设置是否仍然功能完整。
- 确认本轮优化不改变后端路由、权限模型、数据库、MCP 网关、Agent Gateway 或任务执行协议。

## 复验结论

前序版本已经把大部分页面内部拆成“总览、操作看板、流程、明细、表单”的结构：

- 项目「AI 智能体」页已经有注册流程、注册与脚本操作台、运行闭环、节点处置、节点列表和注册表单。
- 项目「任务组」页已经有总览、处置看板、生命周期和展开详情阅读路径。
- 项目「执行监控」页已经有总览、处置看板、实时回送链路和明细表。
- 项目「设置」页已经有总览、操作看板、职责分区、生效流程、规则治理概览和具体配置表单。

本轮从“用户第一次进入项目管理时如何理解左侧栏目”的角度继续复验，发现项目管理侧栏仍然是平铺菜单：

`项目概览、成员权限、AI 智能体、任务组、执行监控、人工审核、人工指令、项目设置`

这个顺序已经符合执行路径，但缺少分组标签。普通用户需要自己判断哪些属于准备、哪些属于执行、哪些属于人工控制、哪些属于治理配置。

### P1：项目管理侧栏缺少栏目分组

现象：

- 项目管理有 8 个入口，页面含义跨度较大。
- 左侧菜单只显示平铺列表，没有把“准备与接入”“执行推进”“人工控制”“治理配置”分开。
- 页面内部已经做了图形化操作台，但入口层仍然像功能清单。

影响：

- 用户会把“成员权限、AI 智能体、任务组、监控、审核、指令、设置”当成同一层级的杂项功能。
- 第一次接入 Agent 或创建任务组时，用户仍要读每个菜单描述才能判断下一步。
- 即使项目首页有操作路径，用户切到其他项目页后，左侧导航仍缺少上下文提示。

处理方案：

- 保持项目管理页面顺序不变。
- 在项目管理侧栏增加栏目分组：
  - 项目总览：项目概览。
  - 准备与接入：成员权限、AI 智能体。
  - 执行推进：任务组、执行监控。
  - 人工控制：人工审核、人工指令。
  - 治理配置：项目设置。
- 继续保留每个菜单项的用途说明和红点计数。
- 补充行为门，要求项目管理侧栏必须存在这些栏目，并且每个栏目必须出现在对应页面入口之前。

### P2：稳定性与性能判断

本轮优化属于纯前端导航结构增强：

- 不改服务端。
- 不新增接口。
- 不新增轮询。
- 不新增依赖。
- 不改变任何权限判断。
- 不改变项目页面实际渲染内容。

因此不会影响高并发、高流量场景的服务端性能，只会减少用户在管理入口层的认知成本。
