# 管理界面第十四轮多角度复验与优化方案（2026-09-03）

## 复验范围

前十三轮已经把系统管理、组织管理、项目管理三个空间拆开，并为高密度页面补齐总览、操作看板、风险提示和跳转入口。本轮从普通中文用户第一次进入后台、日常巡检和紧急处置三条路径继续复验：用户是否不用点进每一页，就能从左侧菜单理解“这个入口管什么、适合什么时候点、和当前空间是什么关系”。

复验角度包括：

- 中文后台习惯：左侧菜单不应只有抽象名词。普通管理者更习惯“标题 + 一句用途”，先扫菜单，再进入模块。
- 管理空间边界：系统管理、组织管理和项目管理已经分开，但菜单短标题仍无法解释职责边界，容易把“系统设置”“项目设置”“AI 智能体”“执行监控”等入口读成相近功能。
- AI-native 边界：后台只负责管理入口、权限、监控和少数人工关口；菜单说明需要明确哪些页面是系统级、组织级、项目级，避免用户以为任务要由人手工执行。
- 信息完整性：不减少现有菜单、页面、卡片、表格和操作按钮，只给现有入口补充更可扫描的说明。
- 性能边界：菜单说明直接复用 `PAGE_META` 中已存在的页面副标题，不新增接口、不新增轮询、不新增依赖、不引入第二套页面说明真相源。
- 移动端边界：移动端横向菜单空间有限，二级说明应在窄屏隐藏，只保留原有短标题和待办徽标，避免撑开页面。

## 发现的问题

- 侧栏菜单当前只显示“系统概览 / 组织管理 / 系统设置 / 账号与授权”等短标题。用户需要点进去读首屏，才知道每个入口具体管什么。
- 项目空间里的“人工审核、人工指令、执行监控、项目设置”含义差异很大，但在菜单上都是同级短词；普通用户不容易判断先去哪里看待办、哪里看实时执行、哪里改配置。
- 组织空间里的“AI 智能体”和项目设置里的“智能体接入”容易混淆。前者是组织级节点运行与吊销，后者是项目级加入令牌签发；菜单没有提前说明。
- 系统空间里的“系统设置”并不是普通偏好设置，而是模型能力、技能源和指令协议等基础能力注册；短标题无法提示它的风险级别。
- 这类问题跨所有页面存在，继续单页补卡片收益变小，应从全局导航层处理。

## 优化方案

- 为左侧菜单增加二级说明，桌面端显示“菜单标题 + 页面用途说明 + 待办徽标”。
- 二级说明直接取 `PAGE_META[pageId][1]`，继续以 `PAGE_META` 作为页面标题与用途的唯一前端真相源。
- 调整菜单按钮 HTML 结构：标题和徽标在同一行，说明单独一行，保持按钮仍然通过 `data-menu` 导航。
- 增加 `.nav-item-main`、`.nav-item-title`、`.nav-item-desc` 样式，让菜单更像中文后台的模块目录，而不是单列按钮。
- 移动端隐藏 `.nav-item-desc`，保留原先横向导航行为；待办徽标仍显示在标题旁。
- 补充行为门，断言所有登记页面的菜单说明来自 `PAGE_META`，防止后续新增页面只加标题不加用途说明。

## 验收要求

- 桌面页面：系统、组织、项目三个管理空间的侧栏菜单显示页面用途说明，且与 `PAGE_META` 保持一致。
- 移动端页面：390px 宽度下二级说明隐藏，菜单不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器分别登录系统管理员、组织管理员和项目成员视角，检查三类菜单说明、空间切换和窄屏表现。
