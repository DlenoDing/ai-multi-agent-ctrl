# 管理界面与执行链路复验 round47

日期：2026-09-04

## 复验结论

本轮按“普通中文用户登录后台后能否清楚完成管理控制”推演系统管理、组织管理、项目管理、任务组、Agent 与执行监控。系统管理与组织管理边界已经拆开，组织子账户、项目/任务组授权、项目仓库凭据和组织/项目级 Agent 档案已具备基础管理入口。但任务组和执行监控仍存在两个认知断点：

1. 任务组详情里，工作项、模型选择、会话放置、派发、执行事件、Git 检查点散落在不同表里。人要理解“某个任务到底经历了哪些 Agent、角色、模型、规则和证据”，需要手动对多个 ID，阅读成本高。
2. 执行监控页底层表齐全，但缺少项目内任务组维度的图形化监控入口。人看到派发、会话、关闭门等表时，不能先按任务组判断哪个组更急、哪个组正在跑、哪个组卡在关闭门。

## 已实施优化

1. 新增“任务执行时间线”：在任务组详情中合并工作项、模型选择记录、会话放置记录、Agent 派发、执行事件和 checkpoint，按时间倒序展示。每条记录标明类型、状态、角色、模型、Agent、派发 ID、进度或 Git 证据。
2. 新增“任务组监控矩阵”：在执行监控页按任务组展示进度、活跃派发、工作会话、关闭门阻塞和最近事件。点击卡片后直接切换实时事件监听范围到对应任务组。
3. 保持底层表格不丢失：时间线和矩阵只是入口与聚合视图，原有实时事件流、派发表、会话表、控制命令、节点、模型选择、准入、检查点、质量门和关闭门明细仍保留。
4. 对账本集合使用显式窗口：模型选择、会话放置和执行事件都保留显示上限，避免用户误以为当前聚合就是完整历史。

## 仍按既有设计保持不变

1. 不新增独立文件管理；任务产出仍落项目 Git 仓库。
2. 不把 MCP 服务下放到 Agent；Agent 仍通过服务端 Gateway、远程 MCP 和服务端同步的 Skill 工作集执行。
3. 运行中重复问题只收集，不在系统运行时自动升级改造。
4. 管理界面只做观察、授权、控制、定稿和纠偏入口，不改变 AI-native 执行主线。
