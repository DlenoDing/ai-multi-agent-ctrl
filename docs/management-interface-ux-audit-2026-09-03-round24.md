# 管理界面第二十四轮复验与优化方案

## 复验范围

- 项目设置、任务组详情和系统设置中的规则配置阅读路径。
- 中文用户管理习惯：先扫状态与来源，再按需展开编辑正文。
- 功能完整性：规则 ID、标题、启用状态、来源、正文、删除、新增、保存都必须保留。
- 性能边界：只调整前端渲染结构和样式，不新增接口、不增加轮询、不改变服务端规则语义。

## 当前结论

前序轮次已经补齐系统/项目管理空间分离、项目 Agent 独立入口、项目概览操作路径、任务组详情阅读路径等结构问题。继续从真实页面推演后，剩余最明显的问题集中在规则编辑器：系统规则正文很长，项目设置页和任务组详情页会把每条规则的完整 textarea 默认展开，导致用户打开配置区后需要滚过大量规则正文，才看得到后续配置或操作入口。

这不是功能缺失，而是信息呈现方式不适合普通中文后台管理：多数时候用户先需要确认“有哪些规则、来自哪里、是否启用、是否被本层覆盖”，只有真正要修改某条规则时才需要进入完整正文。

## 问题清单

1. 规则列表默认展开所有正文，长规则会把页面变成内容墙。
2. 规则来源、启用状态、标题和正文编辑混在一起，普通用户难以先快速扫读。
3. 样式里已有 `.rule-content-view` 和 `.rule-collapsed` 的历史折叠意图，但当前渲染没有输出预览块，折叠样式没有生效。
4. 如果只限制 textarea 高度，会保留页面噪音；如果删除正文，会丢功能。正确形态应是摘要先行、正文按需展开编辑。

## 优化方案

1. 将已有规则行改为 `<details>` 结构：默认折叠，摘要显示规则标题、来源、启用状态、覆盖状态和正文预览。
2. 展开后显示原有编辑表单：标题输入、启用开关、删除按钮、正文 textarea，保持提交收集逻辑不变。
3. 新增规则行默认展开，避免用户点“新增规则”后还要再展开才能填写。
4. 补充样式：摘要行具备清晰点击 affordance，预览最多两行，展开后正文 textarea 高度更适合编辑。
5. 补充行为门：验证已有规则默认折叠、摘要信息完整、textarea 仍存在并可提交、新增规则默认展开。

## 实施记录

- 已将已有规则行改为 `<details>` 折叠结构：摘要先显示规则标题、来源、启用状态、继承/本层覆盖和正文预览，完整正文与编辑控件在展开后可用。
- 已让新增规则行默认展开，点“新增规则”后可以直接填写 ID、标题和正文。
- 已补齐规则摘要桌面三列、移动端单列样式，避免长标题和长预览在窄屏挤压。
- 已修正“新增规则”时只清理 `.small.muted` 的问题，现在系统规则空态警告和业务规则空态提示都会被正确移除。
- 验证结果：`node --check apps/control-plane-ui/public/app.js` 通过；`node --check scripts/console-behaviour-check.mjs` 通过；`npm run console-behaviour-gate` 通过，576 条断言全部通过。
