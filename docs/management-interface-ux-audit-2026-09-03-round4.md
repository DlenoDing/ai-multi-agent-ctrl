# 管理界面第四轮多角度复验与优化方案（2026-09-03）

## 复验角度

本轮在前三轮“管理空间分离、项目模块入口、账号/任务组/监控总览”完成后继续复验。检查重点转向剩余高密度页面：普通中文管理者进入页面后，是否能先看懂当前规模、风险和下一步，再进入表单、长表或只读配置。

复验角度包括：

- 入口顺序：高频查看动作应先于低频创建动作；状态总览应先于配置表单和长表。
- 管理闭环：页面应明确“当前状态是什么、风险在哪里、下一步去哪里处理”。
- 中文用户习惯：先用短标题和指标块建立认知，再给明细；避免首屏直接堆字段。
- 信息完整性：只重排和补充入口，不删除原有表格、按钮、字段、权限和审计信息。
- 性能边界：新增总览只聚合当前已加载视图数据，不新增接口、不扩大轮询、不引入前端框架。

## 发现的问题

- 「系统管理」→「系统设置」仍从运行参数直接进入技能源、模型能力、指令压缩、共享定义等明细。信息完整，但缺少顶部状态地图，普通管理员不能快速判断模型、技能、MCP、共享定义、指令压缩分别是否正常。
- 「组织管理」→「成员管理」首屏仍先显示创建成员表单和说明，再显示成员列表。管理者更常见的动作是先查看现有成员、邀请状态、停用/注销风险，再决定是否新建。
- 「组织管理」→「AI 智能体」有列表/卡片切换和加入令牌，但缺少一个面向管理者的节点运行总览。用户需要读完整表或悬浮详情，才能判断在线率、忙碌节点、待用令牌和当前任务压力。
- 前三轮已经补过的页面需要继续加行为门保护，避免后续迭代又把表单或长表挪回首屏。

## 优化方案

- 新增“系统设置总览”：展示运行状态、MCP 工具数、模型数量、可用模型、技能源、可用技能源、角色叠加、共享定义，并给出查看顺序。
- 新增“成员管理总览”：展示成员总数、启用成员、待接受邀请、已停用、已注销、可授权项目，并把“成员列表”前置到创建表单之前。
- 新增“智能体运行总览”：展示节点总数、在线节点、忙碌节点、待用加入令牌、当前任务数、异常节点，并保留原列表/卡片切换与加入令牌管理。
- 补充控制台行为门，断言系统设置、成员管理、AI 智能体三个页面必须先出现总览，再进入长表或创建/加入令牌模块。

## 验收要求

- 桌面页面：系统设置、成员管理、AI 智能体均先出现总览；成员管理先显示列表，再显示创建表单。
- 移动端页面：390px 宽度下新增总览不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、contract:check、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录，逐页检查系统管理与组织管理页面的首屏顺序和可读性。

## 实施结果

- 已新增“系统设置总览”，并在真实系统管理员登录态下验证它位于“运行参数（只读）”“技能源”“模型能力注册（只读）”之前。
- 已新增“成员管理总览”，并将成员管理页调整为“总览 → 成员列表 → 创建成员 → 说明”，避免组织管理员先看到创建表单。
- 已新增“智能体运行总览”，并保留原有“智能体节点”列表/卡片切换和“加入令牌管理”。
- 已补充行为门断言，覆盖系统设置、成员管理、AI 智能体三页的首屏顺序。
- 已完成真实浏览器 390px 窄屏检查：新增系统设置总览无页面级横向溢出；组织成员/智能体页的身份态由行为门夹具覆盖。
