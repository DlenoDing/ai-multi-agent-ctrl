# 第二十轮管理界面复验与优化方案

## 复验范围

- 项目管理空间的二级栏目：项目概览、任务组、人工审核、人工指令、执行监控、AI 智能体、项目设置。
- 项目设置页的配置对象、运行对象和规则对象是否仍然混在一起。
- 任务组、监控、审核和指令页是否已有总览、操作看板和可跳转入口。
- 中文用户从“我要改项目配置”与“我要接入 Agent”两个意图进入页面时，是否能快速判断入口。

## 现状判断

1. 项目级 AI 智能体页已经独立，承担项目节点查看、一次性 join token、注册脚本、远程 MCP 生效确认。
2. 系统账号页已经补充跨项目边界说明，常规 Agent 注册路径已回到项目 AI 智能体页。
3. 任务组页已有任务组总览和处置看板；执行监控页已有监控总览和处置看板；人工审核页已有待办处置看板；人工指令页已有指令操作看板。
4. 项目设置页已有“项目设置总览”和“项目设置操作看板”，但看板后直接进入“项目基础配置 → AI 智能体 → 系统规则 → 业务规则”。对普通中文用户来说，这仍然像一条长配置页，缺少“本页负责什么、跳去哪里、哪些配置会影响派发”的职责分区。

## 发现的问题

1. 项目设置页的首屏没有明确区分三类对象：配置落点、运行接入、规则约束。
2. “AI 智能体”面板已经只是跳转引导，但它与“项目基础配置”“系统规则”“业务规则”同级排列，仍容易被读成项目设置的一部分。
3. “项目设置操作看板”给了入口，但缺少下一层说明：仓库和默认角色会影响派发；系统规则/业务规则会影响执行约束；Agent 节点和注册脚本不在本页处理。
4. 行为门只检查项目设置页有总览、操作看板和各模块顺序，没有检查项目设置页是否给出职责分区。

## 优化方案

1. 在“项目设置操作看板”之后新增“项目设置职责分区”面板。
2. 分区面板用图形化卡片拆成四类：
   - 产出与基线：仓库、凭证引用、基线材料。
   - 角色回退：项目默认角色与角色 skill 引用。
   - 执行规则：系统规则、业务规则和任务组覆盖边界。
   - Agent 接入：跳转到“AI 智能体”页，不在项目设置页签发脚本。
3. 保留所有现有功能和信息，不删“项目基础配置”“AI 智能体”“系统规则”“业务规则”面板。
4. 行为门新增断言：项目设置页必须按“总览 → 操作看板 → 职责分区 → 项目基础配置 → AI 智能体 → 系统规则 → 业务规则”顺序渲染，并必须出现“Agent 节点和注册脚本不在本页处理”的说明。

## 实施与复验记录

- 已在项目设置页新增“项目设置职责分区”面板，放在“项目设置操作看板”之后、“项目基础配置”之前。
- 新面板以图形化卡片拆成四个入口：产出与基线、角色回退、执行规则、Agent 接入。
- 已明确提示：项目设置只维护会影响派发和产出落地的配置；运行节点、一次性 join token、安装脚本、远程 MCP 生效确认统一进入“AI 智能体”页。
- 已保留所有原有功能和信息：“项目基础配置”“AI 智能体”“系统规则”“业务规则”面板仍完整存在。
- 已补充 `console-behaviour-gate` 断言：项目设置页必须按“总览 → 操作看板 → 职责分区 → 项目基础配置 → AI 智能体 → 系统规则 → 业务规则”的顺序渲染，并必须出现“Agent 节点和注册脚本不在本页处理”的说明。
- 已完成静态语法检查：`node --check apps/control-plane-ui/public/app.js`、`node --check scripts/console-behaviour-check.mjs`。
- 已完成界面行为门：`console-behaviour-gate` 通过，562 条断言全部通过。
- 已完成契约检查：`contract:check` 通过，275 条检查全部通过；指路核对已覆盖 104 个真实面板。
