# 项目成员与任务组权限闭环复验

日期：2026-09-06  
状态：实施中

## 目标

把组织子账户进入项目后的权限管理补成完整闭环：能查看、能授予、能变更、能收回，并保证界面显示角色与服务端真实生效权限始终一致。人只负责账号、授权和必要审核；AI 总控仍负责任务拆解、Agent 选择、调度、执行与实时回送。

## 已确认问题

### P0：项目角色变更只改显示，旧权限仍然有效

`POST /api/projects/:id/members` 会替换 `project.members` 中的角色，但每次都新增一张 `accessGrants`，没有撤销同一账号在同一项目上的旧活动授权。

可复现结果：先授予项目管理员，再授予观察者；项目成员列表显示观察者，但 `accountEffectivePermissions` 会合并两张活动授权，账号仍保留项目管理员能力。这是权限降级失效和界面/真实权限不一致问题。

处理：项目角色采用单值替换语义。写入新角色前撤销该账号在该项目上的旧活动项目授权，再新增唯一活动授权。项目创建者的负责人身份不可通过普通角色表单降级。

### P0：项目成员只能加入，不能移出

当前没有移出项目 API，也没有控制台入口。组织管理员若要阻止某个成员继续访问单个项目，只能停用整个组织账号；这会错误影响该成员在其它项目中的工作。

处理：新增受项目授权权限保护、真人专属的项目成员撤销动作。移出项目时同时撤销该项目角色和该项目下全部任务组角色，并清除指向该项目的默认项目指针；不影响组织账号和其它项目。

### P1：任务组角色更新会叠加旧角色

任务组授权表单使用通用 `access-grants` 创建接口。先授予评审人、再授予观察者会留下两张活动授权，最终仍拥有评审权限。

处理：控制台任务组角色表单明确发送“替换现有角色”，服务端只在该显式标志存在时撤销同一账号、同一任务组的旧活动授权；通用 API 和 MCP 的默认叠加能力保持不变。

### P1：项目成员页缺少成员对象详情

项目成员列表只显示姓名、角色和一句角色影响，没有该成员在当前项目下的任务组角色、真实授权状态、角色变更和移出项目的对象上下文。项目管理员必须在多个栏目重复选择账号。

处理：新增项目成员对象详情。列表只负责定位；详情集中显示项目角色、任务组角色、账号状态、角色变更、任务组授权和移出项目，并保留返回原列表的焦点。

### P1：系统组织详情没有单独显示子账户数量

系统管理员能看到“成员（含管理员）”，但无法直接区分初始组织管理员与组织子账户，也看不到启用、待邀请、停用、注销的子账户构成。

处理：组织详情增加子账户总数及状态分布。系统管理员仍只观察数量和组织风险，不在系统空间管理子账户；具体生命周期操作继续由组织管理员完成。

### P0：初始组织管理员只能重置登录，不能更换账号

系统管理员可重置现有初始管理员的密码和会话，但无法在管理员离职、邮箱失效或身份需要交接时建立新的组织管理员。组织内创建成员的接口明确禁止创建 `org_admin`，最后一个组织管理员又不能被停用或注销，因此当前流程会形成治理死锁。

处理：新增系统级“更换初始组织管理员”。系统管理员必须明确填写新管理员姓名、邮箱，并明确选择旧管理员“停用”或“保留为普通成员”；新账号以待接受邀请状态创建并只显示一次登录令牌。旧管理员立即失去组织管理身份和全部组织级直接权限，活动会话撤销；项目所有权和其它项目记录不被暗中改写。

## 已确认无需重做

- 系统管理只管理组织、初始组织管理员、配额和启停，职责边界已经独立。
- 组织成员详情已经能固定账号和项目上下文分配项目、任务组角色。
- 组织级与项目级 Agent 档案/运行节点已分层，项目视图会同时展示当前项目可调配的两级资源；组织共享节点动态覆盖本组织项目已有端到端测试。
- 项目、任务组、任务三层进度和任务倒序时间线已经实现。
- 任务详情已展示每次派发的 Agent、角色、模型、推理、规则、事件和 Git 证据，并可进入指定任务人工指令。
- 执行监控已有项目总览、任务组监控矩阵和按任务组/派发/会话实时事件范围；权限按具体任务组检查。

## 验收条件

- 项目管理员改成观察者后，旧管理员授权为 `revoked`，真实权限不再包含管理员能力。
- 任务组评审人改成观察者后，旧评审授权不再生效。
- 移出项目后，该账号看不到项目，也没有该项目下任何任务组授权；其它项目权限保持不变。
- 项目创建者不能通过普通成员操作被降级或移出。
- 系统管理员可以更换初始组织管理员；旧管理员立即失去组织管理能力，新管理员使用只显示一次的令牌登录。
- 项目成员详情可直接查看和管理当前项目角色、任务组角色及移出操作，不需要跨栏目重新选择账号。
- 系统组织详情能区分初始管理员和组织子账户，并展示子账户状态构成。
- 全量验证、关键变异、真实浏览器与外部复审均无未处置高风险问题。
