# 第三十五轮管理界面与成员授权流程复验

## 复验范围

本轮继续复验系统管理、组织管理、项目管理三类空间的中文操作路径。前几轮已经补强项目 Agent 注册、任务组生命周期、人工审核和人工指令流程。本轮重点转向成员管理与项目授权，因为它们决定“谁能创建项目、谁能注册 Agent、谁能控制任务组、谁能做人审定稿”，是普通用户最容易误解的权限入口。

## 发现的问题

### P1：成员管理页有总览和操作看板，但缺少授权闭环图

成员管理页已经把成员列表、创建成员、邀请状态和说明分开，也有操作看板。但普通中文用户仍需要自己理解：创建成员只是账号入网，项目角色和任务组权限不在同一处直接完成，后续还要到项目成员授权中分配角色，最后用户才会在任务组、人工审核、Agent 管理等页面看到可操作按钮。

影响：

- 用户可能以为“创建成员”就等于完成项目协作授权。
- 用户不容易区分组织成员权限、项目角色、任务组级审核/控制权限。
- 授权完成后应该回项目页检查任务组、Agent、审核入口是否可操作，当前页没有图形化闭环。

### P2：成员权限与项目权限的边界需要更显性

系统设计中，系统管理、组织管理、项目管理必须分开；Agent 和项目属于用户管理空间，常规注册入口在项目级 AI 智能体页。成员管理页应该提醒：本页只处理组织成员生命周期，项目协作授权要进入项目列表的“项目成员授权”，任务组级审核/控制权限要通过项目角色落位。

### P3：优化必须保持轻量

成员管理页不应新增后端接口或读取更多大集合。流程图应只使用当前已加载的成员、项目和权限数据，通过既有跳转机制引导用户，不改变权限模型和审计模型。

## 改进方案

1. 在组织成员管理页增加“成员授权流程”图形化面板，放在“成员管理操作看板”之后、“成员列表”之前。
2. 流程面板用六张卡片串起：邀请成员、等待登录、分配项目、授任务组角色、回项目操作、审计收口。
3. “分配项目 / 授任务组角色”跳转组织项目列表，“回项目操作”跳转项目概览，“审计收口”跳转成员列表。
4. 明确创建成员不等于完成项目协作授权，任务组级审核/控制必须通过项目成员授权落位。
5. 补充行为门，断言成员管理页必须按“总览、操作看板、流程、成员列表、创建成员、说明”的顺序渲染，并覆盖组织成员、项目授权、任务组权限和项目操作闭环。

## 已实施

2. 流程面板用六张卡片串联：邀请成员、等待登录、分配项目、授任务组角色、回项目操作、审计收口。
3. “分配项目”和“授任务组角色”跳转组织项目列表，“回项目操作”跳转项目概览，“审计收口”跳转成员列表。
4. 面板明确创建成员只完成账号入网，不等于已经能参与项目；任务组控制和人工审核必须通过项目角色与具体任务组作用域落位。
5. 行为门升级成员管理页断言，要求页面按“总览、操作看板、流程、成员列表、创建成员”的顺序渲染，并覆盖组织成员、项目授权、任务组权限和项目操作闭环。

## 外部互审结论

按职责边界复审，本轮改动没有把项目授权或任务组权限混入系统管理页；组织成员页仍只处理组织账号生命周期，项目协作授权继续回到组织项目列表和项目成员授权，Agent 操作仍回到项目级 AI 智能体页。

按性能复审，本轮新增面板只复用现有成员、项目和权限统计，不新增 API、不新增轮询、不读取技能正文或大集合，不改变后端授权、审计和状态写入路径。

按中文交互复审，成员管理页从“总览 → 操作看板 → 成员列表 → 创建表单”升级为“总览 → 操作看板 → 授权流程 → 成员列表 → 创建表单”，更符合先理解边界、再定位对象、最后操作的管理习惯。
