# 第三十八轮管理界面与组织治理流程复验

## 复验范围

本轮继续按系统管理员、组织管理员、项目负责人的中文操作习惯复验系统管理、组织管理、项目管理、Agent 管理、任务组、执行监控、人工审核、人工指令和项目设置。重点检查前几轮补齐项目/账号/设置流程后，是否仍存在跨层级治理路径需要用户自行推导的问题。

## 发现的问题

### P1：系统组织管理页缺少组织开通后的交接流程

系统“组织管理”页已有组织管理总览、组织与配额操作看板、组织列表、创建组织和说明，但仍主要围绕列表和表单。系统管理员需要自己推导组织创建后的完整流程：创建组织、设置配额、交付初始组织管理员、再由组织管理员管理成员/项目/Agent，最后系统管理员只保留启停和配额治理。

影响：

- “创建组织”看起来像最后一步，但实际只是开通入口，后续还要把管理责任交给组织管理员。
- 配额、成员、项目、Agent 的职责边界分散在说明里，没有形成可点击流程。
- 停用组织是高影响治理动作，缺少从配额压力或异常状态到停用/恢复的清晰路径。

### P2：组织 AI 智能体页缺少组织级节点处置闭环

组织“AI 智能体”页已有运行总览、治理操作看板和管理边界，但仍缺一条从组织视角处理节点问题的流程：先看在线率和异常节点，再回目标项目签发新节点，运行中看负载和派发，必要时审计令牌或吊销节点。

影响：

- 组织管理员知道节点异常，但不一定知道新增节点必须回目标项目签发 join token。
- 节点暂停、恢复、关停、吊销和“立即切断”的治理顺序不够直观。
- 组织页和项目页的 Agent 管理边界已经说明，但缺少按处置顺序组织的流程卡。

### P3：优化必须保持简单和稳定

本轮只新增纯前端流程面板和行为门，不新增接口、轮询、状态集合或写入路径。所有卡片使用已加载状态、现有 `data-jump-panel` 和 `data-menu` 跳转。

## 改进方案

1. 系统“组织管理”页新增“组织开通治理流程”，放在“组织与配额操作看板”之后、“组织列表”之前。
2. 组织开通流程包含：创建组织、设置配额、交付管理员、组织侧建设、系统级启停、审计说明。
3. 组织“AI 智能体”页新增“组织 Agent 治理流程”，放在“智能体管理边界”之后、“智能体节点”之前。
4. 组织 Agent 流程包含：看在线率、定位异常、项目注册、负载监控、令牌审计、节点处置。
5. 补充控制台行为门，固定页面顺序、关键边界文案和可达跳转。
6. 完成语法检查、控制台行为门、完整验证和本地服务走查。

## 已实施

1. 系统“组织管理”页已新增“组织开通治理流程”，把组织创建、配额调整、管理员交接、项目侧建设、启停治理和职责审计按操作顺序串联，并保留到组织列表、账号授权和项目空间的图形化入口。
2. 组织“AI 智能体”页已新增“组织 Agent 治理流程”，把在线率、异常节点、项目注册、负载监控、令牌审计和节点处置放入同一条治理路径；明确项目级注册脚本、远程 MCP 生效确认、Skill 工作集和派发回送仍回目标项目处理。
3. 正常空态也保留异常处置提示，避免“当前无异常”时用户看不到后续异常出现后的处理顺序。
4. 行为门已新增组织开通治理流程和组织 Agent 治理流程断言，固定页面顺序、关键中文文案、项目注册入口和执行监控入口。
