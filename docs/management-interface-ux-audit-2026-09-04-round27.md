# 第 27 轮管理界面复验与改进记录

日期：2026-09-04

## 本轮复验目标

从中文用户的阅读、管理和控制习惯重新检查系统管理、组织管理、项目管理、任务组、监控、Agent 注册与 Skill/MCP 边界，继续补齐“功能完整但入口不够清楚”的问题。重点保持三条原则：

1. 系统管理、组织管理、项目管理不混在一起。
2. Agent 常规注册必须发生在对应项目管理页，注册脚本由服务端按一次性 join token 生成。
3. 组织级页面只做跨项目节点总览、管控、吊销和令牌审计，避免让管理员误以为可以绕过项目边界注册 agent。

## 发现的问题

### P1：组织级 AI 智能体页仍容易被误解为常规注册入口

前几轮已经把项目级「AI 智能体」页补齐为“总览 → 操作看板 → 注册流程 → 项目智能体节点 → 注册 agent”，但组织级「AI 智能体」页仍保留了加入令牌签发表单，并且操作卡片会跳到本页的「加入令牌管理」。

这会带来两个问题：

- 中文用户看到“节点接入 / 签发令牌”会自然认为组织页也是正常注册入口。
- 系统设计要求 agent 注册到具体项目下，脚本与 join token 都应在项目管理里获取；组织页保留签发表单会削弱这个边界。

## 改进方案

1. 组织级「AI 智能体」页改为“令牌审计”面板，只展示组织范围 token 状态和撤销入口，不再展示签发表单。
2. 组织级操作看板里的“节点接入 / 项目注册入口”改为跳转当前项目的「AI 智能体」页。
3. 组织级页面文案明确说明：新增机器优先进入目标项目「AI 智能体」页签发一次性令牌；组织页只做节点状态、控制、吊销和令牌审计。
4. 行为门增加防回归检查：组织页不得渲染 `data-form="join-token"`，项目页必须继续保留注册表单和注册脚本来源。

## 验证计划

- `node --check apps/control-plane-ui/public/app.js`
- `node --check scripts/console-behaviour-check.mjs`
- `npm run console-behaviour-gate`
- 本地浏览器桌面与移动视口走查项目级 Agent 注册入口、系统管理入口和项目管理入口。
- 停止本地服务后运行 `npm run validate` 与 `npm run docker:doctor`，确认源码门与 Docker 启动门都通过。

## 已实施结果

1. 组织级「AI 智能体」页保留“智能体运行总览、智能体接入操作看板、智能体管理边界、智能体节点、加入令牌审计”。
2. 组织级「加入令牌审计」只展示 token 状态和撤销入口，不再渲染 `data-form="join-token"`。
3. 组织级“项目注册入口”和“节点接入”卡片改为跳转当前项目的「AI 智能体」页，避免把组织页当作常规注册入口。
4. 项目级「AI 智能体」页继续保留完整注册流程、注册 agent 表单、一次性 join token 和服务端安装脚本来源说明。
5. 首页、边界说明和操作看板文案同步为“组织管控/审计，项目注册/脚本获取”的一致口径。
