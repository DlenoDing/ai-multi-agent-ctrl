# 第四十轮管理界面与规则治理复验

## 复验范围

本轮继续按普通中文用户的管理路径复验系统管理、组织管理、项目管理、任务组、执行监控、人工审核、人工指令、项目设置和 Agent 管理。重点检查前几轮已经补齐 Agent 注册、节点处置、仓库产出归属概览后，是否仍有高密度页面因为明细过长而影响阅读和管理。

## 已确认可接受的页面

1. 项目“AI 智能体”页已经包含总览、操作看板、注册流程、运行闭环、节点处置流程、节点列表和注册入口，能回答“agent 怎么注册、脚本哪里来、离线后怎么处理、何时看监控”。
2. 项目“任务组”页已经包含总览、处置看板、生命周期、统一语言、Agent 准备、监控和关闭门路径。
3. 项目“执行监控”页已经包含总览、处置看板、实时回送链路、节点恢复提示和明细表。
4. 项目“人工审核”页已经包含总览、处置看板、人工审核流程、人机边界、监控回看和关闭门闭环。
5. 项目“人工指令”页已经包含总览、操作看板、结构化指令流程、流水、表单和监控回看。

## 发现的问题

### P1：项目设置规则区缺少规则治理概览

项目“项目设置”页已经有设置总览、操作看板、职责分区、配置生效流程、项目基础配置、AI 智能体入口、角色 Skill 定制、系统规则和业务规则。功能完整，但系统规则数量较多，真实页面会出现很长的系统规则列表。

影响：

- 用户进入规则区前只能看到“系统规则 32 / 业务规则 0”，不知道其中多少来自默认规则、多少是项目新增、多少被停用或改写。
- “系统规则”和“业务规则”都是长明细，缺少一个规则治理层先解释两类规则的职责、覆盖关系和保存入口。
- 普通用户容易把规则列表当作纯文本说明，而不是可治理配置。

### P2：优化必须保持简单、稳定和高性能

本轮只新增纯前端规则概览面板和行为门，不新增接口、轮询、状态集合、数据库字段或后端写路径。概览只使用已加载的 `projConfig` / effective config 与现有 `data-jump-panel` 跳转。

## 改进方案

1. 在项目“项目设置”页新增“规则治理概览”，放在“角色 Skill 定制”之后、“系统规则”之前。
2. 概览展示系统规则总数、业务规则总数、默认系统规则、项目级系统规则、已停用系统规则和已改写系统规则。
3. 概览明确：系统规则负责执行安全和流程边界，业务规则负责项目约束，任务组可继续覆盖。
4. 概览提供跳转到“系统规则”和“业务规则”的图形化入口，不替代原规则明细和保存动作。
5. 补充控制台行为门，固定页面顺序、规则治理关键文案和跳转入口。
