# 管理对象与操作路径复查

基线：`3bece85`。本轮延续既有系统／组织／项目作用域、仓库凭据、共享 Agent、规则编辑器和任务工作台，不重复重建已验证的后端能力。目标是让对象、范围、状态和下一步操作在实际使用位置可见。

## 本轮确认的问题

| 问题 | 证据与影响 | 处理方向 |
| --- | --- | --- |
| 组织项目列表无法直接进入项目 | `renderOrgProjects` 的列表行只有归档，进入项目按钮在说明栏目中 | 项目名称可进入；每行提供成员、设置等明确入口，归档作为独立次要操作 |
| 概况重复且操作离对象太远 | 项目概况重复显示进度、状态，并展示七张大菜单卡片；任务组一览没有行级入口 | 单份项目摘要、紧凑状态入口，任务组行直达详情、任务和监控 |
| 创建按钮重复 | 工作区通用标题和列表标题可同时显示同一个创建按钮 | 通用工作区只在没有对象列表主操作时补按钮，确保单一主入口 |
| 成员授权没有保留对象 | 成员行“项目与任务组授权”只跳到全量矩阵；后续表单要重新选择成员 | 携带成员上下文进入授权工作区，清楚显示当前成员与资源角色 |
| 当前所属组织缺少明确展示 | 项目／组织顶栏只显示账号名与管理空间，难以判断组织归属 | 展示服务端授权范围内的组织信息，项目与任务组继续显式标识 |
| 从任务跳到监控后难以回到原任务 | 跨页仅保留任务组范围，原任务和列表位置容易丢失 | 保留受项目／账号约束的任务来源，提供返回任务入口，不缓存跨账号内容 |

## 实施约束

- 不新增人工执行阶段，不改变总控自动调度、模型决策、MCP 集中部署或按任务同步 Skill。
- 不因界面入口增加而扩大权限；显示与操作仍基于服务器的项目、任务组、账号能力判定。
- 公共对象导航与摘要提取到独立界面模块，避免新增成片的主文件模板。
- 完整信息放在对应对象详情或独立栏目，不通过删除功能和证据来缩短页面。
- 真实用户正在使用的预览页不作破坏性测试；交互验收使用隔离测试运行态。
