# 第三十四轮管理界面与人工审核流程复验

## 复验范围

本轮继续按普通中文用户的管理路径复验系统：系统管理、组织管理、项目概览、AI 智能体、任务组、执行监控、人工审核、人工指令和项目设置。前几轮已经把系统/项目职责边界、项目级 Agent 注册入口、任务组生命周期和集中 MCP/Skill 同步原则补齐。本轮重点转向“人工审核”和“人工指令”两个人类介入入口，因为它们是 AI-native 系统中人唯一高频参与执行控制的位置。

## 发现的问题

### P1：人工审核页仍缺少页级处理流程图

人工审核页已经有“人工审核总览”和“人工审核处置看板”，但进入页面后仍会很快落到待办、待确认、授权、审批、发现项、历史等长内容。对普通中文用户来说，这些模块都重要，但缺少一张图把“为什么我要处理、先处理什么、处理后看哪里”串成主线。

影响：

- 用户知道有多少待办，但不一定知道处理动作会影响 AI 派发、关闭门和实时监控。
- 定稿、授权、审批、发现项都在同一页，容易被读成普通列表，而不是 AI 执行链路中的阶段门。
- 处理完成后应回到执行监控或任务组页看结果，但当前页没有显性回路。

### P2：人工审核的人机边界可以更明确

系统设计要求 AI 不在运行中自行升级系统，人只负责目标、权限、语言、定稿和必要控制。人工审核页是这个边界最容易被误读的地方：用户需要看到“AI 提交材料，人做不可替代的决策，系统再按决策继续执行”的流程，而不是只看到表单。

### P3：不能为了清晰而增加重依赖

人工审核页读取的对象很多，包括确认、授权、审批、发现项和历史。优化必须基于已经加载的当前项目数据，不新增接口、不新增轮询、不搬动后端状态模型，以免影响高并发和高流量场景。

### P4：人工指令页也缺少结构化输入流程边界

人工指令页已经有总览和操作看板，但看板之后直接进入指令流水和下达表单。用户容易把它理解成“给总控会话发消息”，而系统真实语义是：人工指令只生成结构化输入，由下一编排周期消费，并按任务组权限、状态机和审计规则执行。

影响：

- 用户不容易理解为什么指令不是立即直接改总控会话。
- 被拒绝的指令应先看拒绝原因再重提，但当前流程提示不够显性。
- 指令被消费后的结果需要回执行监控看实时回送和控制 ACK，当前页没有形成闭环。

## 改进方案

1. 在人工审核页增加“人工审核流程”图形化面板，位置放在“人工审核处置看板”之后、“待你处理”之前。
2. 流程面板用六张卡片串起：待办入口、方案定稿、授权审批、发现项处置、执行回看、历史追溯。
3. “执行回看”跳转执行监控，“方案定稿/授权审批/发现项处置/历史追溯”跳转本页对应面板，形成清晰闭环。
4. 在人工指令页增加“人工指令流程”图形化面板，位置放在“人工指令操作看板”之后、“指令流水”之前。
5. 人工指令流程面板用六张卡片串起：选任务组、选指令类型、提交输入、编排消费、核对结果、回看运行。
6. 两个流程面板都只使用当前页面已计算的计数，不新增 API、不读取更多大集合、不改变权限判定。
7. 补充行为门，断言人工审核页必须按“总览、处置看板、流程、待你处理”的顺序渲染，人工指令页必须按“总览、操作看板、流程、流水、表单”的顺序渲染，并覆盖人机边界、结构化输入、编排消费、实时回送、关闭门和历史追溯提示。

## 已实施

1. 人工审核页新增“人工审核流程”图形化面板，放在“人工审核处置看板”之后、“待你处理”之前。
2. “人工审核流程”用六张卡片串联待办入口、方案定稿、授权审批、发现项处置、执行回看、历史追溯，并把执行回看跳转到执行监控页。
3. 人工审核流程明确 AI 只提交结构化材料和互审，人只在目标、权限、风险、定稿和必要纠偏处介入。
4. 人工指令页新增“人工指令流程”图形化面板，放在“人工指令操作看板”之后、“指令流水”之前。
5. “人工指令流程”用六张卡片串联选任务组、选指令类型、提交输入、编排消费、核对结果、回看运行，并明确人工指令是结构化控制输入，不是给总控会话直接发聊天消息。
6. 行为门新增并升级两类断言：人工审核页必须显示流程图并覆盖人机边界、监控回看和关闭门闭环；人工指令页必须显示流程图并覆盖结构化输入、编排消费、拒绝原因和控制 ACK 回看。

## 外部互审结论

按职责边界复审，本轮改动没有把任何服务性能力下放到 Agent 端，也没有改变“项目级 Agent 注册、服务端集中 MCP、服务端同步 Skill、Agent Runtime 只执行”的设计原则。人工审核与人工指令两个页面仍只做真人入口和项目内控制，不混入系统管理能力。

按性能复审，本轮新增内容只使用页面内已经计算出的计数和现有跳转，不新增 API、不新增轮询、不读取技能正文、不扩大主视图集合，也不改数据库分片策略。对高并发高流量路径没有新增服务端负担。

按中文交互复审，本轮把两个人类介入入口从“总览/看板之后直接读长表”改为“总览 → 处置看板 → 流程图 → 明细/表单”，更符合先理解、再定位、后操作的中文管理习惯，同时保留原有全部明细、表单和审计信息。
