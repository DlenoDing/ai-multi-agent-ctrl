# 任务对象工作区与执行轨迹

基线为 `111deaa`。本轮保留已完成的系统／组织／项目权限、项目仓库凭据、组织共享节点和规则编辑能力，继续处理任务组与任务的真实阅读和管理路径。

## 问题与方案

| 当前问题 | 实施方案 |
| --- | --- |
| 任务组列表每项都是较高的状态、操作卡片，详情又嵌在其中 | 列表改为紧凑表格；进入任务组后使用独立对象工作区，保留明确返回列表、创建任务、启动／暂停、监控、审核与指令入口 |
| 任务详情每次执行的字段与事件全部铺开 | 用有序执行轨迹组织运行记录，摘要直接呈现角色、节点、模型、时间和状态，元数据、规则与事件按次展开 |
| 失败派发可能被误画为“已执行” | 执行阶段依据实际事件、认领信息和已完成检查点，不把任意终态当成执行器已启动的证据 |
| 刷新后只记住栏目，丢失正在查看的任务组或任务 | 保存按账号和项目绑定的工作区定位，只保存对象 ID、栏目及列表位置，不保存令牌或正文；恢复时仍通过服务端鉴权读取 |
| 新工作区可能藏掉旧控制与审阅能力 | 保留原有控制表单和阶段门，只改变它们所属的对象工作区；只读用户不增加写权限 |
| Agent 空闲时同时显示暂停与恢复，超时节点仍计在线 | 派发按钮按当前任务状态二选一；没有当前派发时不下无目标命令。组织与项目 Agent 汇总沿用心跳超时口径 |

- [x] 执行轨迹、按次展开与阶段证据正确性。
- [x] 刷新定位恢复、跨账号隔离和失效对象处理。

定位保存仅用于恢复本地界面，不作为授权依据；执行过程仍由 AI 总控、运行节点和服务器推进，不新增人工执行阶段。

## 实现结果

- 任务组列表改为可扫描表格，显示执行状态、进度、真实任务数、服务端角色数、语言、更新时间和状态相关操作。任务组详情是独立对象工作区，不再嵌在其他组卡片中；可返回列表，并直达任务、监控、审核、指令和当前项目 Agent。
- 独立详情从受保护的进度接口获取完整身份摘要及 `canControl`／`canReview`，因此窗口外但已授权的任务组也能恢复。摘要不重复工作项和阻塞大载荷；操作仍调用原任务组控制接口。
- 任务执行记录按派发时间正序组织，每次显示状态、执行角色、节点、模型和时间。详细元数据、本次规则与执行事件按次展开；折叠状态在页面刷新时保留。执行器未启动就失败的派发不会被标成“执行任务已完成”。
- 浏览器工作区定位只保存账号、项目、栏目、任务组／任务 ID、筛选和游标，不保存令牌、规则正文、任务正文或执行结果。恢复时先按账号匹配，再通过服务器接口重新鉴权；任务详情响应还要同时匹配项目、任务组和任务 ID 才能进入缓存。
- 仅在本地恢复的项目已被服务端明确拒绝（403／404）时，清除旧定位并重新读取可见项目，避免用户被困在无项目选择器的错误页；网络失败和手工选择仍原样报错，不静默跳转。
- Agent 页面注册、节点、可调配角色及说明各自独立；公共标题不再重复“创建／注册”入口。项目角色页显示组织名称，解释三个自动模型预设；任务组可直接进入当前项目 Agent 管理。
- Agent 当前任务数统一读取运行节点公开的派发 ID。空闲节点不显示无目标的暂停／恢复；运行中只显示暂停当前任务，阻塞时只显示恢复当前任务。项目和组织汇总继续排除心跳超时节点。
- 一个节点有多个当前任务时，节点行只进入执行监控；暂停、恢复和取消放在每条派发行并明确携带派发 ID，分别按对应任务组权限判定，不再默认控制派发数组第一项。
- 登录 DTO 的顶层 `passwordSet` 优先于兼容字段 `authPolicy.passwordSet`。已设置密码的账号显示“修改密码”，修改表单要求当前密码；旧会话缓存仍兼容。

## 验证记录

1. 真实浏览器管理员视角：在有三个任务组的项目检查紧凑列表，进入独立任务组详情后刷新仍停留原组；从工作项进入真实完成任务，看到组织共享节点、角色档案、显式模型与推理、选型判断、规则、十条过程事件、Git 推送和检查点。
2. 真实浏览器普通观察者视角：独立账号仅获得一个项目和任务组的观察者授权；可进入并刷新恢复任务组与任务详情，不显示创建、启动、暂停、评审或纠偏操作。390 × 844 下页面宽度保持 390，无横向溢出或脚本错误。
3. 执行轨迹浏览器复验：折叠执行次数后点击刷新仍保持折叠；再次展开后事件默认收起，可按需查看完整十条过程记录。
4. Agent 浏览器复验：项目节点页显示组织共享节点、心跳超时／离线、一个当前任务和“暂停当前任务”，没有同时显示恢复；注册项目节点页只有一个入口，可调配角色页显示“组织级：Org Node Scope A”及模型预设说明。
5. 自动测试新增：任务组身份摘要权限与跨项目拒绝、定位字段白名单／账号隔离／完整游标栈、窗口外任务组恢复、错配任务响应拒绝、执行阶段证据、折叠状态、只读旧创建偏好回退、Agent 按派发状态二选一控制。
6. 外部 Claude 只读复审任务对象、恢复绑定、执行轨迹和 API 摘要，未发现阻塞缺陷；提出的 `expandedTaskGroupId` 耦合风险由服务端摘要项目校验、列表找不到时的明确返回入口和自动测试共同约束。最终 Agent 与密码状态改动另做收尾复审。

## 原需求对照

- 系统管理的组织、初始组织管理员、启停与配额，组织管理员的子账户及项目／任务组授权，继续由既有系统／组织工作区负责。
- 项目仓库账号密码和 API Key／Token 继续按项目独立加密保存、读写检测，不改成环境变量引用。
- 项目／任务组规则继续自动增高并支持全屏编辑；组织共享节点和项目专属节点的调配、中央 MCP、按派发 Skill 工作集与实时回送机制保持不变。
- 项目进度、任务组进度、倒序任务列表、任务完整执行流程以及人工启动、审核、复核、指令入口，分别落在项目摘要、任务组对象、任务工作台和对应控制栏目中，不通过本地文件管理替代 Git 产出。

确定性 Runtime 验证证明注册、调配、过程回送、Git 提交和检查点链路，不等同于所有外部付费模型供应商的线上调用，也不作为生产高并发压测结论。
