# 管理界面第二轮多角度复验与优化方案（2026-09-03）

## 复验范围

本轮从普通中文用户的管理路径、系统管理员/组织管理员/项目成员的空间边界、项目设置的信息层级、运行状态可信度、窄屏布局、文档口径和维护成本七个角度复验控制台。目标不是删功能，而是在保留系统完整信息的前提下，让用户能更快理解“现在在哪、这里管什么、下一步去哪、状态是否正常”。

## 复验结论

系统管理、组织管理、项目管理已经完成主空间分离，项目侧功能也已经覆盖任务组、审核、指令、监控、项目设置与智能体接入。但仍有几处会影响普通用户阅读和管理控制的问题：

- 系统概览的“服务健康”汇总存在误判：服务表显示健康，但总览卡片可能显示 `0/15`。原因是总览同时要求 `health` 和 `status` 都命中绿色状态，而运行态 `running` 没被计入绿色集合。
- 项目设置页功能齐全，但第一屏缺少“设置总览”。仓库、基线、默认角色、智能体接入和规则配置直接纵向堆叠，普通用户需要读完整页才能知道这个项目配置完整度。
- 多处提示仍使用旧称“Agent 入网授权”，或者只写“系统设置页”“账号与授权里”，和当前三空间导航不完全一致。
- 项目设置页面描述仍未明确包含“智能体接入”，用户从顶部标题和说明无法第一时间判断 agent 注册入口在这里。
- 历史复验文档里仍保留“项目空间指向 AI 智能体页”的旧问题描述，需要补充现态，否则后续维护会按旧路径理解。

## 优化方案

- 修正系统概览服务健康计算，只以 `health` 作为健康度主口径；运行态仍在服务明细表展示，不参与健康汇总，避免健康与生命周期状态混淆。
- 在项目设置页增加“项目设置总览”图形化指标区，展示仓库数、基线数据数、默认角色数、待用加入令牌数、系统规则数、业务规则数，并保留原有所有编辑表单。
- 将项目设置页面说明改为“仓库与凭证引用、基线数据、智能体接入、规则与默认角色”。
- 将用户可见提示统一到完整中文路径，例如「系统管理」→「系统设置」、「系统管理」→「账号与授权」、「项目管理」→「项目设置」→「智能体接入」。
- 同步 README、运行时协议和系统设计文档里的 agent 入网入口描述，保证下载安装到后续注册操作都指向同一管理路径。

## 实施结果

- 已按健康主口径修正系统概览，真实页面复验显示 `15/15 服务健康`，与服务明细表一致。
- 已在项目设置页增加“项目设置总览”，并保留原有仓库、基线、默认角色、智能体接入、系统规则、业务规则全部功能。
- 已统一运行界面、README、Agent Runtime 协议与系统设计文档里的 agent 注册入口为「项目管理」→「项目设置」→「智能体接入」。
- 已将跨空间提示改为完整路径，减少中文用户在当前菜单里找不到入口的概率。

## 验收要求

- 本地页面复验：登录系统管理员后，系统概览服务健康应显示真实健康数量，项目设置页第一屏应能看到设置总览和智能体接入入口。
- 代码门：`node --check`、`git diff --check`、`console-behaviour-gate`、`mutation-anchors`、`contract:check`、`validate`、`docker:doctor` 通过。
- 视觉与交互：桌面与 390px 窄屏下页面不出现主体溢出；表格类明细保留横向滚动容器，不把内容硬挤到不可读。
- 维护性：不新增后端接口，不扩大实时状态载荷，不引入新的前端状态机；所有新增总览均复用当前已加载状态。
