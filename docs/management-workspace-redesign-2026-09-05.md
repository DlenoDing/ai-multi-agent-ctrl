# 管理工作区重构与功能闭环

本轮基线为 `9df05ef`。目标按用户的系统、组织、项目、任务组、任务层级重构操作路径，保留完整信息和 AI-native 自动执行，不以增加说明卡片替代管理能力。

## 现状与缺口

1. 系统与组织菜单已分开，但组织、项目、配置、审核、监控等页仍重复显示概览、看板、流程和操作，实际对象列表被挤到后面。
2. 组织成员和两级权限已有真实接口，上轮修复了同组织授权对象错用默认账号的问题。本轮保留并复验，不重做身份体系。
3. 项目仓库已支持单独保存账号密码或 API Key、加密存储和读写检测。需要把仓库配置从规则及角色配置中分离成清楚的工作区。
4. 规则正文默认高度仍小；任务组详情内的规则编辑还受多层容器宽度影响。
5. 组织级 Agent 档案已能被选中，但加入令牌和运行节点仍只注册到单个项目，组织共享机器的实际调配能力未闭环。
6. 监控页的执行事件选择以任务组为主，页面其他集合仍按整个项目展示；项目总览与任务组观察需要统一、显式的范围。
7. 任务组详情同时承载事项、任务、规则、角色、控制和历史，没有独立任务工作台；创建任务与查阅任务执行过程仍需反复展开长卡片。

## 目标结构

| 层级 | 独立工作区 | 核心操作 |
| --- | --- | --- |
| 系统 | 运行概览、组织管理、系统能力 | 开通组织和初始管理员、启停、配额；不承载组织子账户日常管理 |
| 组织 | 组织概览、成员与授权、共享 Agent、项目列表 | 创建子账户、授项目／任务组权限、注册共享节点、创建／进入项目 |
| 项目 | 概览、任务组、任务工作台、Agent、监控、审核、指令、仓库与配置 | 每个业务对象有明确入口，创建操作靠近列表，跨模块跳转保留项目上下文 |
| 任务组 | 任务、进度监控、角色与规则、执行控制 | 明确当前组，统一语言，查看或创建任务，暂停／恢复、审核及纠偏 |
| 任务 | 概要、执行过程、规则、结果与证据 | 按时间倒序列任务；按实际执行顺序展示会话、节点、角色、模型、过程事件与产出 |

## 实施边界

- 页面使用功能工作区导航及对象详情，避免同时堆叠所有面板；原有帮助按需展开，关键状态和异常保留在当前操作区。
- 组织共享节点和项目专属节点分别持有注册作用域。组织共享节点仅服务本组织当前有效项目；新项目可被覆盖，跨组织始终拒绝，空项目集合不得解释成无限权限。
- 组织级加入令牌只由组织管理权限签发，项目管理权限不能借此扩大为组织权限。MCP 服务、技能来源和派发仍集中在服务端。
- 监控范围贯穿事件、派发、会话、控制、审核与门禁；选择任务组后不夹带其他组的记录或操作。
- 规则编辑自动增高并支持宽屏编辑，保留来源、继承、只读、保存失败恢复和冲突检查。
- 抽取新的页面组织、任务工作台、规则编辑公共模块，避免继续扩大主文件。保留既有角色名称和显式模型决策规则。
