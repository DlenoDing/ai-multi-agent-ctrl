# 管理工作区重构与功能闭环

本轮基线为 `9df05ef`。目标按用户的系统、组织、项目、任务组、任务层级重构操作路径，保留完整信息和 AI-native 自动执行，不以增加说明卡片替代管理能力。

## 现状与缺口

1. 系统与组织菜单已分开，但组织、项目、配置、审核、监控等页仍重复显示概览、看板、流程和操作，实际对象列表被挤到后面。
2. 组织成员和两级权限已有真实接口，上轮修复了同组织授权对象错用默认账号的问题。本轮保留并复验，不重做身份体系。
3. 项目仓库已支持单独保存账号密码或 API Key、加密存储和读写检测。需要把仓库配置从规则及角色配置中分离成清楚的工作区。
4. 规则正文默认高度仍小；任务组详情内的规则编辑还受多层容器宽度影响。
5. 组织级 Agent 档案已能被选中，但加入令牌和运行节点仍只注册到单个项目，组织共享机器的实际调配能力未闭环。
6. 监控页的执行事件选择以任务组为主，页面其他集合仍按整个项目展示；项目总览与任务组观察需要统一、显式的范围。
7. 任务组详情同时承载事项、任务、规则、角色、控制和历史，没有独立任务工作台；创建任务与查阅任务执行过程仍需反复展开长卡片。

## 目标结构

| 层级 | 独立工作区 | 核心操作 |
| --- | --- | --- |
| 系统 | 运行概览、组织管理、系统能力 | 开通组织和初始管理员、启停、配额；不承载组织子账户日常管理 |
| 组织 | 组织概览、成员与授权、共享 Agent、项目列表 | 创建子账户、授项目／任务组权限、注册共享节点、创建／进入项目 |
| 项目 | 概览、任务组、任务工作台、Agent、监控、审核、指令、仓库与配置 | 每个业务对象有明确入口，创建操作靠近列表，跨模块跳转保留项目上下文 |
| 任务组 | 任务、进度监控、角色与规则、执行控制 | 明确当前组，统一语言，查看或创建任务，暂停／恢复、审核及纠偏 |
| 任务 | 概要、执行过程、规则、结果与证据 | 按时间倒序列任务；按实际执行顺序展示会话、节点、角色、模型、过程事件与产出 |

## 实施边界

- 页面使用功能工作区导航及对象详情，避免同时堆叠所有面板；原有帮助按需展开，关键状态和异常保留在当前操作区。
- 组织共享节点和项目专属节点分别持有注册作用域。组织共享节点仅服务本组织当前有效项目；新项目可被覆盖，跨组织始终拒绝，空项目集合不得解释成无限权限。
- 组织级加入令牌只由组织管理权限签发，项目管理权限不能借此扩大为组织权限。MCP 服务、技能来源和派发仍集中在服务端。
- 监控范围贯穿事件、派发、会话、控制、审核与门禁；选择任务组后不夹带其他组的记录或操作。
- 规则编辑自动增高并支持宽屏编辑，保留来源、继承、只读、保存失败恢复和冲突检查。
- 抽取新的页面组织、任务工作台、规则编辑公共模块，避免继续扩大主文件。保留既有角色名称和显式模型决策规则。

## 已实现的变更

1. `workspaces.js` 统一管理功能栏目归属。项目仓库、基线、角色 Skill、系统规则、业务规则分开保存；组织成员列表、创建和权限矩阵分开；系统管理不再承载组织子账户日常操作。旧帮助保留在说明栏目，列表之前不再叠放多层引导。
2. `runtime-node-scope.mjs` 统一组织共享节点的动态调配范围，Gateway、MCP、容量计算、心跳和浏览器投影使用同一口径。组织尚无项目时可以完成注册、自检，但不能访问其他组织；注册以后创建的有效项目可实际派发到该共享节点。
3. `task-workbench.js` 提供独立任务列表与详情，列表按创建时间倒序、服务端检索和游标分页；详情读取完整工作项，而非把摘要当完整结果。展示实际派发、会话、节点、逻辑角色档案、执行角色、模型与推理、选型判断、过程事件、执行规则和结果证据。
4. 项目和任务组监控共用显式范围，实时事件与完整历史分开。权限过滤在事件分页前执行，长轮询结束重新核验授权；切换项目、账号、任务或实时／历史模式时，过期响应不得覆盖当前页面。历史保留到分段事件日志，未加载的数据明确标示。
5. 规则输入自动增高，支持全屏编辑和只读查看。全屏期间不重渲染表单；保留原位置镜像字段用于登录过期草稿恢复。取消不会覆盖后台替换后的新规则；若权限变为只读，应用修改被拒且草稿保留。保存沿用打开表单时的配置版本，冲突不会覆盖新版本。
6. 创建项目后进入该项目，创建任务组后进入组详情，创建任务后进入任务详情。任务组可勾选等待手动启动，服务端原子创建暂停态；自动循环不会抢先派发，显式启动后再恢复自治执行。人工审核与指令仍是后台控制入口，不把人引入默认 Agent 执行链路。
7. 初始组织管理员邀请可重发，旧令牌失效。普通成员账号能力与具体资源角色分开：账号级仅暴露“允许创建项目”，项目和任务组的操作、审核、Agent 权限仍绑定资源授权。只读成员不显示创建任务、创建任务组或注册节点快捷按钮。
8. 有创建能力的普通成员在顶栏直接创建本人项目，不必进入组织管理员菜单。服务端视图返回最新账号能力，避免登录缓存使授权或撤销不生效；组织成员能力配置单独处理 `project:create`，不放宽普通邀请或资源授权的委派限制。显式空权限数组可以真正清空，省略字段则保留原值，未知权限拒绝而不是静默忽略。

## 性能与边界

- 默认任务页 50 条、服务端上限 100 条；实时事件仅在可见实时栏目请求，历史模式不跟随后台轮询重复读取整段日志。最新事件使用尾窗，增量请求复用按项目、任务组、权限范围和过滤条件区分的等待者。
- 任务历史显式分页并不等于存储已拥有任意规模的随机查询索引：从最早事件开始回补仍可能读取完整项目事件历史。千万级事件的生产延迟与并发用户容量未在本轮压测，不宣称无限扩展。
- Runtime 门使用确定性测试执行器和本地测试 Git 仓库，验证真实注册、调配、过程回送和提交链路，不计为所有付费模型供应商的线上验收。
- 浏览器与运行门均使用隔离测试运行目录，不改用户原有项目数据。历史审计文档保留当时事实；当前注册范围以 README、Agent Runtime 协议与本文为准。
- 本地预览使用 `.runtime/workspace-redesign-20260905`，监听 `127.0.0.1:4317`；自治周期关闭、测试 Runtime 已停止，不会自动消耗模型额度。共享测试节点会如实显示心跳超时，此状态不是仍在运行的承诺。
