# 第三十三轮管理界面与任务组流程复验

## 复验范围

本轮继续按中文项目负责人、系统管理员和旁路审核者的实际阅读路径推演管理界面，重点检查项目日常操作核心页：任务组、AI 智能体、执行监控、人工审核、项目设置。目标不是增加复杂功能，而是让现有 AI-native 执行链路在界面上更清晰：人设置目标、权限、语言、角色和审批边界；系统总控自动拆解、派发、监控、纠偏；Agent 节点只运行 Runtime 并实时回送。

## 发现的问题

### P1：任务组页缺少页级生命周期图

任务组页已经具备“任务组总览”和“任务组处置看板”，也有展开后的详情阅读路径。但普通用户首次进入任务组页时，仍需要自己把“创建任务组、拆工作项、确认 Agent、执行监控、人工定稿、关闭门收口”拼成一条主线。对于中文管理界面来说，这会让页面显得像功能堆叠，而不是可操作流程。

影响：

- 用户知道当前有多少任务组和阻塞，但不一定知道下一步应该进入哪个模块。
- Agent 注册入口已经在项目 AI 智能体页，但任务组页没有把“无 Agent 时去哪里处理”做成明显路径。
- 关闭门、人工审核、实时监控的关系分散在多个菜单，旁路审核者需要跨页理解执行状态。

### P2：任务组创建表单前缺少流程承接

当前顺序是总览、处置看板、创建表单、任务组列表。这个顺序比早期直接堆表单好，但用户在进入表单前仍缺少一张“该先看什么、后做什么”的图形化路径。创建任务组和创建工作项是关键操作，应当被生命周期说明承接，而不是孤立出现。

### P3：Agent 注册与实时回送在任务组页没有形成显性依赖

项目 AI 智能体页已清楚说明注册脚本、集中 MCP、Skill 同步和 Runtime 回送；执行监控页也有实时回送链路。但任务组页作为日常入口，应该用轻量图形入口提醒：工作项真正执行前必须有项目 Agent 节点，运行中状态要去执行监控看实时事件和控制 ACK。

## 改进方案

1. 在任务组页增加“任务组生命周期”图形化面板，位置放在“任务组处置看板”之后、“创建任务组/创建工作项”之前。
2. 生命周期面板用六个可点击卡片串起主线：创建任务组、拆工作项、确认 Agent、运行监控、人工定稿、关闭收口。
3. 面板只使用当前页面已经加载的任务组数据，不新增 API、不读取大集合、不引入新的轮询或存储压力。
4. 卡片跳转使用既有 `data-jump-panel` 与 `data-menu` 机制，保持界面交互简单稳定。
5. 补充行为门，断言任务组页必须按“总览、处置看板、生命周期、创建表单”的顺序渲染，并覆盖 Agent 注册入口、实时监控、人工审核和关闭门提示。

## 已实施

1. 任务组页新增“任务组生命周期”图形化面板，放在“任务组处置看板”之后、创建表单之前。
2. 生命周期面板用六张卡片串联：创建任务组、拆工作项、确认 Agent、运行监控、人工定稿、关闭收口。
3. “确认 Agent”卡片跳转项目级「AI 智能体」，并明确注册入口在「项目管理」→「AI 智能体」。
4. “运行监控”“人工定稿”“关闭收口”卡片分别跳转执行监控和人工审核，避免用户在任务组页看完状态后不知道下一步去哪里处理。
5. 任务组总览底部提示同步改为先看处置看板和生命周期，再决定创建、追加工作项或进入 Agent/监控/审核模块。
6. 行为门新增任务组生命周期断言，覆盖渲染顺序、Agent 注册入口、实时回送、人工审核、关闭门和 AI-native 执行边界。

## 外部互审结论

按系统边界和性能角度复审，本轮没有引入新的服务端状态、数据库集合、轮询、MCP 工具或 Agent Runtime 依赖；新增内容是纯前端导航和说明，使用已有跳转机制与当前已加载任务组数据。改动满足“简单、稳定、性能都要”的约束，不会把服务性组件下放到 Agent 端，也不改变项目级 Agent 注册和集中 MCP/Skill 同步原则。

残余风险：本仓当前没有 Playwright/Puppeteer 依赖，本轮未新增浏览器自动化依赖以避免安装变重；真实浏览器检查保留为内置浏览器人工走查，核心结构由行为门和真实服务内容检查兜底。
