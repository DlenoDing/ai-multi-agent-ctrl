# 第三十一轮管理界面与操作闭环复验

## 复验范围

- 系统管理、组织管理、项目管理三类空间是否继续保持职责分离。
- 项目概览、项目设置、项目 AI 智能体、执行监控这些高频入口是否能让中文用户快速判断下一步。
- Agent 查看、注册脚本来源、一次性加入令牌、远程 MCP、Skill 同步、节点自检与运行监控是否形成可操作闭环。
- 本轮改动是否保持简单、稳定、高性能：不新增接口、不新增后台轮询、不改变服务端数据模型，只优化入口信息架构和防回归检查。

## 本轮发现

前几轮已经完成了关键架构方向：常规 Agent 注册只在项目级「AI 智能体」页发生；系统级和组织级页面只做全局治理、审计和节点控制；执行监控页能看实时事件、派发、会话、节点和关闭门。

继续从普通中文项目负责人视角推演后，仍有几处弱点：

- 项目概览的「AI 智能体」卡片有入口，但没有明确写出完整路径和服务端脚本来源；第一次使用的人仍可能不知道脚本从哪里来。
- 项目操作路径里的「执行准备」只说“先注册 agent”，没有把“签发一次性加入令牌、复制服务端安装脚本、确认远程 MCP/Skill 生效”串成一条闭环。
- 执行监控的「节点」处置卡片在无节点时只写“先到 AI 智能体页注册 agent”，没有完整路径；在有异常节点时也没有提醒回项目 Agent 页点“刷新自检”。
- 项目设置里的「Agent 接入」卡片仍像一个附属入口，未强调配置页不处理注册表单、实际注册要去项目级 Agent 页。

这些问题不影响服务端核心链路，但会影响中文用户在界面上快速找到真实操作点，属于 P2 级界面信息架构问题。

## 优化方案

1. 保留现有菜单结构，不新增页面、不拆接口，避免把系统复杂度继续抬高。
2. 在高频入口处统一使用完整路径：「项目管理」→「AI 智能体」→「注册 agent」。
3. 将 Agent 首次接入描述统一为：签发一次性加入令牌、复制服务端安装脚本、在 agent 主机执行、回项目节点列表确认在线/准入/远程 MCP/Skill 生效。
4. 将异常节点处置描述统一为：先看执行监控定位异常，再回项目「AI 智能体」节点行点「刷新自检」或让组织管理员做跨项目治理。
5. 补充 console 行为门，确保项目概览、项目设置、执行监控三个入口都不能退回含糊文案。
