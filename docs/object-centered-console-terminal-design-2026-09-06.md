# 对象中心管理控制台终态改造

日期：2026-09-06  
状态：实施中

## 目标

把控制台从“页面 + 页面内 Tab”改成可定位、可返回、可持续理解上下文的对象中心管理系统。系统、组织和项目是独立管理空间；项目、任务组、任务、Agent 档案、运行节点、会话与派发是可直接进入的对象。人只负责后台治理、入口控制、必要审核与独立指令，任务拆解、模型和 Skill 选择、调度、执行、过程回送与结果收口继续由 AI 总控和 Agent 自动完成。

## 现状证据

1. 管理空间切换位于顶栏，以两个小型 `section-tab` 呈现；切换后左侧菜单整组替换，但空间本身没有成为侧栏第一层，系统管理与项目管理的边界仍像页面 Tab。
2. 当前项目选择器在顶栏，功能菜单在侧栏，任务组范围在内容区。项目、任务组和任务三个上下文分散在三个区域，进入监控、审核或指令后需要重新确认自己正在操作哪个对象。
3. 所有页面 URL 都是 `/`。页面、栏目、项目、任务组和任务只保存在 `sessionStorage`，不能使用浏览器前进/后退，也不能把某个任务或组织详情的地址交给另一位有权限的管理者复核。
4. 桌面侧栏在当前页面下面嵌套栏目；移动端隐藏该栏目，改在内容顶部再渲染一条横向栏目。项目菜单本身在移动端也是横向滚动，因此实际形成两条需要左右滑动的导航带。
5. 任务组详情已有任务、监控、审核、指令按钮，但离开详情后只剩“任务组范围”下拉；当前任务组进度、任务数、在执行数、待审核数和阻塞数不会持续显示。
6. 任务详情有执行阶段和证据，但项目概览到“创建任务组 → 创建任务 → 启动 → 监控 → 审核/复核”的主线仍散落在不同页面，缺少基于当前状态计算的唯一下一步动作。
7. 组织级与项目级 Agent 已真实参与调度，但两处菜单都叫“AI 智能体”，需要依靠二级栏目才能区分档案、运行节点和注册；当前选中的 Agent/节点也不是可保持的对象上下文。
8. 主渲染存在重复 `app.innerHTML = html`，触摸悬浮处理有重复条件，提交成功词表有重复键。前者会把每次必要渲染的 DOM 解析与写入执行两遍。

## 终态信息架构

### 管理空间

- **系统管理**：系统运行、组织列表、初始组织管理员、组织启停与配额、系统模型和技能源。不得承载组织子账户、项目执行或 Agent 日常操作。
- **组织管理**：组织概况、子账户、项目/任务组权限、组织级 Agent 档案和共享运行节点、项目目录。
- **项目管理**：项目概览、成员、项目级 Agent、任务组、任务、监控、审核、指令、仓库和规则。

管理空间选择器固定在侧栏顶部，采用完整名称、当前状态和对象数量，不再作为顶栏小 Tab。项目选择器与项目模块导航放在同一侧栏上下文中。

### 对象上下文

- 侧栏持续显示当前项目；选定任务组后显示任务组名称、进度、状态、任务/运行/待审/阻塞计数。
- 进入任务后继续显示当前任务、负责角色、状态和进度，并提供返回任务组或任务列表的直接动作。
- 内容区保留可点击层级路径，但不重复侧栏的完整信息。
- 桌面使用侧栏对象导航；窄屏使用一个“当前位置/切换栏目”控制，不叠加两条横向 Tab。

### 可寻址工作区

地址只保存对象标识与界面位置，不保存令牌、规则正文、任务正文或结果内容。目标格式：

```text
#/system/organizations/<orgId>
#/organization/members/<accountId>
#/project/<projectId>/task-groups/<taskGroupId>
#/project/<projectId>/tasks/<taskGroupId>/<workItemId>
#/project/<projectId>/monitor/<taskGroupId>
```

登录后按当前账号重新鉴权和读取对象；无权、已删除或跨组织对象必须给出明确提示并回到最近可见上级。浏览器前进/后退必须恢复页面、栏目和对象，不依赖旧账号的本地缓存。

### 操作主线

项目概览只呈现一条按状态计算的主操作：配置仓库、接入 Agent、创建任务组、创建任务、启动任务组、查看执行、处理审核、处理阻塞或查看结果。其它操作保留在对象对应模块，不再同时铺开成说明卡片。

任务组对象提供固定控制头：进度、任务总数、在执行数、待审核数、阻塞数、当前语言和运行状态；任务、监控、审核、指令、Agent 是对象级动作，不要求再次选择任务组。

## 实施顺序

1. [待实施] 新增侧栏管理空间与对象上下文模块，移动管理空间和项目选择，消除顶栏 Tab 语义。
2. [待实施] 新增安全 URL 路由模块，接入菜单、栏目、项目、任务组、任务、组织与成员详情以及浏览器前进/后退。
3. [待实施] 增加任务组持续状态摘要和项目主操作，贯通创建、启动、监控、审核、复核、指令与结果查看。
4. [待实施] 收敛 Agent 命名和对象入口，使组织共享档案/节点与项目专属档案/节点无需靠说明文案区分。
5. [待实施] 移除重复 DOM 写入与重复分支，验证实时刷新、草稿保护和路由不会互相覆盖。
6. [待实施] 完成系统管理员、组织管理员、项目管理员和只读观察者的桌面/窄屏真实操作；运行完整验证与变异门。
7. [待实施] 交由 Claude 从权限边界、对象路由和中文操作认知三个角度复审，修正有效发现后提交推送并保留最新预览。

## 验收条件

- 登录后无需猜测即可区分系统、组织和项目管理空间，系统空间不出现组织子账户或项目执行操作。
- 任一项目执行页面都能看到当前项目；选定任务组或任务后，上下文持续存在且可直接返回上级。
- 可复制地址打开同一对象；另一账号打开时重新鉴权，不能读到缓存中的对象内容。
- 浏览器前进/后退恢复真实对象与栏目，未保存表单仍执行离开确认。
- 从空项目到任务执行、监控、审核/复核和结果查看，每一步只有清楚的当前状态与下一主操作。
- 任务详情完整保留 Agent、运行节点、角色、模型、推理、Skill、规则、事件、Git 证据和结果，不以简化导航为由删除信息。
- 组织级和项目级 Agent 均可建立、注册、查看和控制；任务组自动调度仍可同时选择两级 Agent。
- 390px 窄屏不存在双横向导航、页面级横向溢出、文字重叠或不可达操作。
- 全量验证、关键变异、真实浏览器与外部互审无未处置高风险问题。
