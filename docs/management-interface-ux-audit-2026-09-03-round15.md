# 管理界面第十五轮多角度复验与优化方案（2026-09-03）

## 复验范围

第十四轮已经把侧栏菜单升级为“标题 + 用途说明”的模块目录。本轮继续从全局框架、空间识别和移动端首屏推演，检查用户是否能稳定识别当前所在的管理后台，而不是只依赖页面标题或菜单文字。

复验角度包括：

- 中文后台习惯：左侧品牌区应持续承担“这是哪个系统、当前是哪类管理空间”的定位作用；图形标识不能被普通说明文字样式误伤。
- 空间识别：系统管理、组织管理、项目管理虽然已经分离，但左上角标识和空间名是用户确认当前位置的第一视觉锚点。
- 移动端边界：移动端菜单说明可以隐藏，但品牌图形标识不应随空间说明一起隐藏；否则首屏只剩文字导航，系统识别度下降。
- 样式稳定性：CSS 选择器应精确绑定语义元素，不能用 `.brand span` 这类会同时命中图形标识和说明文字的宽选择器。
- 信息完整性：不减少品牌、空间名、菜单、页面内容和操作入口，只修正样式选择器和 DOM 语义类名。
- 性能边界：纯前端静态结构与 CSS 修正，不新增接口、不新增轮询、不引入依赖。

## 发现的问题

- 侧栏品牌区结构中，图形标识和空间说明都是 `span`，而 CSS 使用 `.brand span` 设置说明文字样式。
- `.brand span` 的选择器比 `.brand-mark` 更具体，会覆盖图形标识的字号与颜色，让“智”标识不够突出。
- 移动端媒体查询里 `.brand span { display: none; }` 会把图形标识也隐藏掉；原意只是隐藏空间说明文字。
- 真实浏览器走查时用 `.brand span` 读取空间名，取到的是“智”，这说明 DOM 语义和样式选择器都不够精确。

## 优化方案

- 给侧栏空间说明增加明确类名 `brand-section`。
- 将桌面说明文字样式从 `.brand span` 改为 `.brand .brand-section`。
- 将移动端隐藏规则从 `.brand span` 改为 `.brand .brand-section`，保留品牌图形标识。
- 保持登录页品牌结构不变；登录页没有空间说明，不需要参与本轮调整。
- 补充行为门，断言侧栏空间说明使用 `brand-section`，且 CSS 不再用 `.brand span` 统配品牌区所有 `span`。

## 验收要求

- 桌面页面：左上角“智”标识保持图形标识样式，空间说明显示系统管理、组织管理或项目管理。
- 移动端页面：空间说明隐藏，但“智”标识仍显示，不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录系统管理员和项目成员视角，检查品牌区文字、图形标识和 390px 移动端表现。

## 实施结果

- 已给侧栏空间说明增加 `brand-section` 类名，明确区分品牌图形标识与空间说明文字。
- 已将 `.brand span` 改为 `.brand .brand-section`，避免说明文字样式覆盖左上角“智”标识。
- 已将移动端隐藏规则改为 `.brand .brand-section { display: none; }`，移动端只隐藏空间说明，不隐藏品牌图形标识。
- 已补充 `console-behaviour-gate`：断言 DOM 输出 `brand-section`，断言 CSS 不再使用 `.brand span` 宽选择器，并断言移动端只隐藏空间说明。
- 已完成本地真实浏览器走查：系统管理员桌面视角显示“智”图形标识和“系统管理”；项目成员桌面视角显示“智”图形标识和“项目管理”；390px 移动端“智”仍显示、空间说明隐藏、无页面级横向溢出。
- 已通过 `node --check apps/control-plane-ui/public/app.js`、`node --check scripts/console-behaviour-check.mjs`、`git diff --check`、`npm run console-behaviour-gate`、`npm run mutation-anchors`。
