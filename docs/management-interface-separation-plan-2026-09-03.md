# 管理界面分离与中文交互优化方案（2026-09-03）

## 问题复盘

当前控制台已经具备系统管理、组织管理、项目管理、任务组控制、实时执行监控、人工审核、人工指令、智能体入网、模型选型、中心化 MCP 与项目分片存储等功能，但界面信息架构仍有明显混杂：

- 系统管理员左侧菜单同时出现系统管理页和项目执行页，用户会把“全局系统配置”和“某个项目的执行控制”读成同一层级。
- 项目页内部大量使用表格和记录块，虽然信息完整，但模块边界不够直观，普通管理者需要读很多文字才能判断下一步去哪里。
- 项目内容分布在“概览、任务组、人工审核、人工指令、执行监控、项目设置”六页，但概览页没有给出清晰的图形化模块入口。
- 顶栏同时承载页面标题、项目切换、账号、时间和操作按钮，移动端虽已收紧，但项目管理入口仍不够像一个独立工作区。
- 部分页面文案更像实现说明或后台字段说明，不完全符合中文用户“先看模块、再看状态、最后点操作”的阅读习惯。

## 目标信息架构

系统分成两类管理空间，入口和侧栏必须分开：

- 系统管理空间：系统概览、组织管理、系统设置、账号与授权。
- 组织管理空间：组织概览、成员管理、AI 智能体、项目管理。
- 项目管理空间：项目概览、任务组、人工审核、人工指令、执行监控、项目设置。

系统管理员和组织管理员可以在顶部切换“系统/组织管理”和“项目管理”，但同一时刻左侧只显示当前空间的菜单。普通用户只进入项目管理空间。

## 中文交互原则

- 先分区，再列表：页面顶部先告诉用户当前处于哪个管理空间，左侧菜单只展示这一空间内的功能。
- 先图形，再表格：项目概览先给出模块卡片和状态摘要，表格保留在下方作为明细。
- 操作用中文动词：按钮尽量使用“进入、查看、处理、配置、监控”等明确动作，减少“排障、视角、档案”等偏工程词。
- 状态用图形化卡片聚合：任务组、待处理、执行事件、仓库产出等关键对象先用卡片呈现数量、状态和入口。
- 高危动作先讲后果：高危操作要先列“会影响什么、是否可撤销、为什么需要确认”，再给按钮。
- 移动端只保留关键首屏：导航单行横向滚动，项目页顶栏保持短结构，避免让菜单和标题占满首屏。

## 本轮实施方案

1. 将菜单定义拆成系统管理、组织管理、项目管理三组，删除系统/组织菜单内嵌的项目页。
2. 增加“管理空间切换”控件：系统管理员看到“系统管理 / 项目管理”，组织管理员看到“组织管理 / 项目管理”，普通用户不显示。
3. 修改页面有效性判断：用户可访问的页面全集与当前显示菜单分离，避免进入项目页后被默认页拉回。
4. 侧栏品牌副标题改为当前管理空间，强化当前所在位置。
5. 在项目概览顶部增加项目模块卡片：任务组、人工审核、人工指令、执行监控、项目设置，用数字和状态说明下一步。
6. 增加项目状态摘要卡片，把项目状态、阶段、健康度、工作进度、任务组、待处理、最近事件、仓库产出先图形化展示。
7. 优化移动端切换控件和模块卡片布局，保证 390px 宽度下无页面级横向溢出。

## 不在本轮做的事

- 不改后端调度、agent 注册、中心化 MCP、实时事件、项目分片数据库与权限模型。
- 不新增前端框架或图标库，避免引入构建和依赖复杂度。
- 不减少原有明细表格，先在上层增加清晰入口和摘要，保证信息完整性。
- 不把人工审核/人工指令改名为机器动作；这些页面是人类管理员控制 AI-native 系统的管理入口，不代表任务由人执行。

## 验收标准

- 系统管理和项目管理在侧栏上完全分离，同一菜单内不再混放两类页面。
- 项目概览首屏能看到模块入口、关键状态和待处理数量，不需要先读完整表格。
- 390px 移动端项目管理页无页面级横向溢出，导航和模块卡片可正常点击。
- 控制台行为门、契约门、全量校验与 Docker 体检保持通过。
