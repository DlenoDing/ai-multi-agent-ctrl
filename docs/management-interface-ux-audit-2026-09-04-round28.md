# 第 28 轮管理界面复验与改进记录

日期：2026-09-04

## 本轮复验目标

继续从普通中文用户的管理路径检查系统管理、组织管理、项目管理、Agent、Skill、权限与执行监控页面。重点不是继续堆信息，而是让入口、职责边界和操作顺序更符合“先看现状、再定位入口、最后执行操作”的管理习惯。

## 本轮发现

### P1：系统级「账号与授权」页仍保留 Agent 入网签发表单

第 27 轮已经把组织级「AI 智能体」页改为令牌审计，不再承载常规注册。但系统级「账号与授权」页仍有「智能体入网令牌」面板，并通过 `renderJoinTokenSection()` 渲染完整签发表单。

这与当前终态要求不一致：

- Agent 属于项目/用户管理，不属于系统管理的常规操作。
- Agent 注册必须绑定目标项目，注册脚本应在对应项目的「AI 智能体」页获取。
- 系统管理页如果仍写“跨项目代签、应急处理”，中文用户会理解为系统管理员可以绕过项目入口常规接入 agent。

## 改进方案

1. 系统级「智能体入网令牌」改名为「智能体入网审计」。
2. 系统级面板只展示跨项目 token 状态和撤销入口，不再渲染 `data-form="join-token"`。
3. 系统级操作看板和职责边界删除“跨项目代签”语义，统一为“令牌审计 / 项目页注册”。
4. 行为门补充检查：系统级「账号与授权」页不得渲染 Agent join token 签发表单，项目级「AI 智能体」页必须继续保留注册表单和脚本来源。

## 验证计划

- `node --check apps/control-plane-ui/public/app.js`
- `node --check scripts/console-behaviour-check.mjs`
- `npm run console-behaviour-gate`
- 本地浏览器桌面/移动视口走查系统级账号与授权、项目级 AI 智能体、执行监控。
- `npm run validate`
- `npm run docker:doctor`

## 已实施结果

1. 系统级「账号与授权」页的「智能体入网令牌」已改为「智能体入网审计」。
2. 系统级「智能体入网审计」只展示跨项目 token 状态和撤销入口，不再渲染 `data-form="join-token"`。
3. 系统级操作看板、职责边界和说明文字删除“跨项目代签 / 应急签发”语义，统一表达为“系统审计，项目注册”。
4. `renderJoinTokenSection()` 的审计模式增加 `context` 区分，系统页显示系统审计提示，组织页显示组织审计提示，避免复用组件时串文案。
5. 行为门新增系统级防回归断言：系统账号页不能承载 Agent 注册表单，也不能复用组织页审计提示。
6. 外部互审建议已采纳：组织页显式传入 `context: "org"`；审计模式在没有项目时也按系统/组织语境说明“没有可审计的 agent 入网令牌”，不再复用签发表单空态。
