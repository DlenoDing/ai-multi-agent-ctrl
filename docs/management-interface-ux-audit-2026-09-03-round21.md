# 第二十一轮管理界面复验与优化方案

## 复验范围

- 项目概览作为普通中文用户进入项目后的第一屏，是否能直接说明下一步应该去哪里。
- 项目概览中的任务组、人工审核、人工指令、执行监控、AI 智能体、项目设置六类入口是否只是并列卡片，还是形成清晰操作路径。
- 已有项目级 Agent 管理、项目设置职责分区、任务组处置看板、监控处置看板、人工审核/指令看板之间的关联是否在项目概览上表达出来。

## 现状判断

1. 项目概览已有项目头、总进度、阶段、健康度、六张模块卡片、关键指标、任务组一览、最新事件和仓库产出归属。
2. 项目概览已经有 AI 智能体入口；无在线节点时能直接进入项目 AI 智能体页注册 agent。
3. 各明细页已经分别补齐总览、操作看板和职责边界。
4. 但项目概览的六个模块入口仍是并列关系。普通用户第一次进入时，仍要自己判断先检查 Agent、再看任务组、还是先去监控/审核。

## 发现的问题

1. 项目概览缺少“推荐操作路径”层。指标和模块都在，但没有把它们按执行顺序串起来。
2. “任务组”“执行监控”“人工审核”“人工指令”“AI 智能体”“项目设置”含义不同，但都以同级卡片呈现，对普通中文用户来说仍然偏后台模块堆叠。
3. 项目概览是最容易被长期盯着的一屏。它应当承担“今天先看哪里、异常去哪处理、配置去哪改”的入口地图职责。
4. 现有行为门只检查项目概览有 AI 智能体入口，没有检查项目概览是否能解释项目各模块之间的操作顺序。

## 优化方案

1. 在项目概览的项目头和模块卡片之后，新增“项目操作路径”面板。
2. 面板按中文管理习惯拆成六个顺序：
   - 执行准备：Agent 在线和仓库产出落点。
   - 任务组织：任务组、目标、角色、工作项和统一语言。
   - 实时监控：派发、会话、节点、事件和关闭门。
   - 人工介入：人工审核、裁决和阻断点处理。
   - 控制补充：人工指令、约束补充和一次性规则注入。
   - 配置调整：项目设置、规则和默认角色。
3. 每一步都用图形化卡片跳转到对应页面或面板，不删除现有模块卡片与明细面板。
4. 行为门新增断言：项目概览必须出现“项目操作路径”，且位于项目头之后、关键指标之前；必须提供任务组、执行监控、人工审核、人工指令、AI 智能体、项目设置的跳转入口。

## 实施与复验记录

- 已在项目概览新增“项目操作路径”面板，放在项目头和模块卡片之后、“项目进度 / 关键指标”之前。
- 新面板按 6 步串联项目管理入口：执行准备、任务组织、实时监控、人工介入、控制补充、配置调整。
- 每一步都使用图形化卡片跳转到真实页面：AI 智能体、任务组、执行监控、人工审核、人工指令、项目设置。
- 已保留项目概览原有项目头、六个模块入口、项目进度、关键指标、任务组一览、最新执行事件和仓库产出归属。
- 已补充 `console-behaviour-gate` 断言：项目概览必须出现“项目操作路径”，且必须位于项目头之后、关键指标之前，并覆盖六个项目管理跳转入口。
- 已完成静态语法检查：`node --check apps/control-plane-ui/public/app.js`、`node --check scripts/console-behaviour-check.mjs`。
- 已完成界面行为门：`console-behaviour-gate` 通过，563 条断言全部通过。
- 已完成契约检查：`contract:check` 通过，275 条检查全部通过；指路核对已覆盖 105 个真实面板。
- 已完成真实浏览器桌面走查：1280 视口下“项目操作路径”位于项目头之后、关键指标之前，六个入口均可见且跳转目标正确；无项目节点时执行准备显示“无节点”，仓库落点数量保留在说明文本中，避免把仓库数量误读为在线 Agent 数。
- 已完成真实浏览器移动端走查：390 视口下操作路径卡片稳定双列排布，核心文字不溢出，“无节点”状态可见，页面无水平滚动。
- 已完成全量验证：`validate` 通过，覆盖规格、契约、权限落点、控制台行为、人工边界、系统不变量、崩溃一致性、并发写入、初始化登录、自治循环空转收敛、真实任务推进和项目分片隔离。
- 已完成 Docker 验证：`docker:doctor` 通过，覆盖 compose 配置、镜像构建、健康检查、中心化 MCP、Agent 安装脚本产物和 PostgreSQL 状态存储。
