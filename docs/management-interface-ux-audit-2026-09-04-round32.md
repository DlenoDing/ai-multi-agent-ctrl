# 第三十二轮管理界面与 Agent 闭环复验

## 复验范围

- 项目管理空间是否能让普通中文用户按“先看状态、再找入口、最后操作”的顺序理解 Agent 接入、运行、控制和回送。
- 系统管理、组织管理、项目管理是否仍保持职责分离：系统看全局，组织做治理，项目做实际注册和项目内控制。
- 执行监控是否能清楚解释服务端如何下发控制、Agent 如何实时回送事件、管理界面如何看详情和纠偏。
- 本轮是否保持简单、稳定、性能：不新增服务端接口、不新增数据模型、不增加后台轮询，只把既有状态组织成更清晰的图形化入口，并加行为门防回归。

## 本轮发现

前几轮已经完成项目级 Agent 页、注册脚本一次性展示、集中 MCP、Skill 工作集同步、实时事件、控制通道和 Docker/验证门。继续从“第一次接手项目的中文负责人”视角推演，仍有几处可优化点：

- 项目级「AI 智能体」页有注册流程，但它偏向安装步骤，没有把“服务端签发、Agent 轻量注册、远程 MCP、Skill 工作集、实时事件、检查点回送、服务端控制”画成一条运行闭环。
- 执行监控页已经有总览和处置看板，但实时链路靠多张表分散呈现；用户看到「实时事件流」「智能体派发」「控制通道」时，需要自己理解这些表之间的关系。
- 部分中文说明仍写“项目 AI 智能体页”“当前项目页”这类半路径；在系统/组织/项目三空间分离后，半路径会让用户找不到入口。
- 源码注释里仍保留“待你处理跨全部可见项目统计”的旧口径，而页面已经改成按当前项目视图统计。这个项目大量后续维护由 AI 执行，过期注释会误导后续改动。

这些问题不属于后端核心缺陷，但会降低管理台的可理解性，尤其影响用户判断“agent 是否已正确接入、任务是否在实时回送、卡住后应该点哪一块”。

## 优化方案

1. 在项目级「AI 智能体」页新增“接入与运行闭环”图形化面板，用卡片串起：
   - 项目签发一次性令牌；
   - Agent 主机只跑轻量 Runtime；
   - MCP 与 Skill Registry 集中在服务器；
   - 任务执行中持续回送事件；
   - 节点控制命令由服务端落盘并通过长轮询送达。
2. 在执行监控页新增“实时回送链路”图形化面板，用卡片说明：
   - 派发和会话；
   - 实时事件；
   - 控制通道；
   - 运行时节点；
   - 关闭门禁。
3. 清理仍然含糊的跨空间指路，统一写成「项目管理」→「AI 智能体」→「注册 agent」或点名具体面板。
4. 修正过期注释，让后续 AI 维护读到的规则与当前实现一致。
5. 扩展 `console-behaviour-gate`，断言新增闭环面板、实时链路面板、集中 MCP/Skill/长轮询/持续回送等关键文案和跳转目标存在。

## 实施记录

- 已在项目级「AI 智能体」页新增「Agent 接入与运行闭环」面板，按卡片说明项目签发、轻量 Runtime、远程 MCP/Skill、实时回送、服务端控制五段链路。
- 已在执行监控页新增「实时回送链路」面板，按卡片串起派发会话、实时事件、控制通道、运行节点和关闭门禁，放在明细表之前。
- 已修正系统/组织/项目空间里仍然含糊的 Agent 注册路径，统一指向「项目管理」→「AI 智能体」→「注册 agent」。
- 已修正「待你处理」相关源码注释和审核看板说明，使其与当前“按项目视图统计”的实现一致。
- 已补充 console 行为门，新增断言覆盖项目 Agent 运行闭环、集中 MCP、最小 Skill 工作集、持续事件回送、服务端控制 ACK、监控实时链路和对应跳转目标。
- 已根据行为门反馈修正一次实现：不在项目闭环卡片里直接读取 `agentControlCommands` 窗口集合计数，避免把服务端截断窗口当成完整总数。
