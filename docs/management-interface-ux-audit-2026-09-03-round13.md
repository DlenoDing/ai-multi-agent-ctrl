# 管理界面第十三轮多角度复验与优化方案（2026-09-03）

## 复验范围

第十一、十二轮已补齐项目级“人工指令”和“人工审核”的图形化处置入口。本轮继续从组织管理员视角复验组织管理侧仍未完全图形化的两个高频页面：“成员管理”和“AI 智能体”。这两页分别管理人侧账号与机器侧 agent 节点，是 AI-native 系统稳定运行的基础入口。

复验角度包括：

- 中文后台习惯：组织管理页面应遵循“总览 → 操作看板 → 当前列表 → 创建 / 接入 / 说明”，让用户先判断风险和规模，再执行新增或停用操作。
- AI-native 边界：成员页只管理人侧账号、邀请和授权入口；智能体页只管理机器节点、接入令牌和节点控制，不把服务性 MCP 能力放到 agent 本地。
- 图形化入口：成员管理总览已有成员总数、启用成员、待邀请、停用、注销和可授权项目，但缺少跳转入口；AI 智能体总览已有节点、在线率、忙碌、任务、令牌和异常节点，也缺少跳转入口。
- 稳定性要求：待接受邀请、已停用、异常节点和待用加入令牌都是运行管理风险，应优先暴露为可点击入口。
- 信息完整性：不减少成员列表、创建成员、权限说明、智能体节点、加入令牌管理和现有操作按钮。
- 性能边界：只基于当前已加载成员、节点、项目和加入令牌聚合，不新增接口、不新增轮询、不引入依赖。

## 发现的问题

- 「成员管理」页当前顺序是“成员管理总览 → 成员列表 → 创建成员 → 说明”。顺序基本正确，但总览后的数字不是可点击入口。
- 用户看到“待接受邀请”“已停用”“已注销”后，不能直接跳到成员列表处理，只能继续读长表。
- 「AI 智能体」页当前顺序是“智能体运行总览 → 智能体节点 → 加入令牌管理”。它直接进入节点表，对在线率、异常节点、令牌接入和节点控制没有入口地图。
- 与系统组织、账号授权、组织项目、项目设置、人工审核、人工指令等页面相比，这两页缺少同形操作看板，组织管理区整体一致性不足。

## 优化方案

- 新增“成员管理操作看板”，放在“成员管理总览”之后、“成员列表”之前。
- 成员看板卡片覆盖：待邀请、启用成员、已停用、已注销、可授权项目、创建成员。
- 待邀请、启用成员、已停用、已注销卡片跳转到“成员列表”；可授权项目跳转到“说明”；创建成员跳转到“创建成员”。
- 新增“智能体接入操作看板”，放在“智能体运行总览”之后、“智能体节点”之前。
- 智能体看板卡片覆盖：在线节点、异常节点、忙碌节点、当前任务、待用加入令牌、节点接入。
- 在线节点、异常节点、忙碌节点、当前任务卡片跳转到“智能体节点”；待用加入令牌和节点接入卡片跳转到“加入令牌管理”。
- 补充行为门，断言成员页和智能体页必须先显示总览和操作看板，再显示列表 / 节点 / 表单 / 说明，并断言看板跳转目标存在。

## 验收要求

- 桌面页面：成员管理页和 AI 智能体页均先显示总览和操作看板，再进入列表、接入或创建区。
- 移动端页面：390px 宽度下新增两个看板不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录成员管理页和 AI 智能体页，检查看板可读性、卡片跳转和窄屏表现。
