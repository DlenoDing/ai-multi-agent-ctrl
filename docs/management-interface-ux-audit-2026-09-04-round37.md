# 第三十七轮管理界面与治理流程复验

## 复验范围

本轮继续按普通中文系统管理员、组织管理员和项目负责人的实际操作路径复验：系统管理与项目管理分离、组织项目管理、账号与授权、组织/项目 Agent 管理、任务组、执行监控、人工审核、人工指令和项目设置。前几轮已经补齐项目设置、系统设置、Agent 注册和任务组/监控的操作看板，本轮重点检查跨页面的管理主线是否还需要用户自己推导。

## 发现的问题

### P1：组织项目管理页缺少项目治理闭环

组织“项目管理”页已经有总览和操作看板，但看板主要指向列表、创建项目和成员授权。普通组织管理员仍需要自己判断项目创建后的下一步：补成员授权、进入项目设置配置仓库/规则/角色 Skill、进入项目 AI 智能体签发 Agent、进入任务组启动执行、最后归档收口。

影响：

- 用户能看到项目列表，但不清楚一个项目从创建到运行的完整治理顺序。
- “项目管理”和“项目设置 / AI 智能体 / 任务组 / 执行监控”之间的关系需要自行推导。
- 项目归档是终态操作，但缺少一条从运行收口到归档的明确路径。

### P2：系统账号与授权页缺少权限处置闭环

系统“账号与授权”页已有总览、操作看板和职责边界，但还缺少一条更像操作流程的主线：先确认账号身份，再审计授权，再处理服务账号和 Agent 档案，再核对入网令牌，最后回到项目空间完成成员授权与 Agent 注册。

影响：

- 系统管理员看到账号、授权、入网令牌和 Agent 档案后，仍要自己判断哪些是系统级，哪些要回项目级处理。
- 常规 Agent 注册已经不在系统页，但系统页仍需要更清楚地把“审计令牌”和“签发项目 join token”分开。
- 账号邀请、访问授权、项目成员授权和 Agent 注册之间的顺序不够直观。

### P3：优化必须继续保持轻量

本轮只改前端信息架构和行为门，不新增接口、不新增轮询、不改状态写入路径。所有新面板只使用已加载状态、现有 `data-jump-panel` 和 `data-menu` 跳转。

## 改进方案

1. 组织“项目管理”页新增“项目治理流程”，放在“项目管理操作看板”之后、“项目列表”之前。
2. “项目治理流程”用六张卡说明：创建项目、成员授权、项目配置、Agent 接入、任务组执行、归档收口。
3. 系统“账号与授权”页新增“账号授权处置流程”，放在“账号与授权职责边界”之后、“账号列表”之前。
4. “账号授权处置流程”用六张卡说明：账号身份、访问授权、服务账号、入网令牌审计、Agent 档案、项目级落位。
5. 补充控制台行为门，固定页面顺序和关键边界文案，防止后续退回长表单堆砌。
6. 完成后运行语法检查、控制台行为门、完整验证和本地服务走查。
