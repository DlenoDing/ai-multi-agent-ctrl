# 第二十二轮管理界面复验与优化方案

## 复验范围

- 项目管理入口是否已经和系统管理、组织管理分开，普通中文用户能否按项目完成日常管理。
- 项目内 AI 智能体页是否能完整回答：当前有哪些节点、怎么注册新 agent、注册脚本从哪里来、注册后如何确认生效、异常节点在哪里处理。
- 页面是否仍存在“只有长表、表单和说明堆叠，缺少图形化查看和操作入口”的问题。
- 本轮只做界面和行为门优化，不改变服务端的 Agent Gateway、远程 MCP、join token 和权限模型。

## 现状判断

1. 系统管理、组织管理和项目管理已经通过左侧空间切换分开，项目概览已经有“项目操作路径”。
2. 项目级 AI 智能体页已经有总览、操作看板、注册流程、节点表和注册 agent 表单。
3. 注册流程已经明确说明：先在项目页签发一次性 join token，再使用服务端返回的安装脚本；agent 注册后通过 node token、Agent Gateway、远程 MCP 和技能工作集交互。
4. 但项目节点仍只有表格视图。普通用户要判断“哪台可用、哪台异常、当前在跑什么、该暂停还是吊销”时，需要横向扫很多列，不够直观。
5. 组织级智能体页已有列表 / 卡片切换，项目级智能体页没有同等图形化管理入口，导致“组织能看卡片、项目只能看表格”的交互不一致。

## 发现的问题

1. 项目 AI 智能体页缺少卡片视图。Agent 管理是项目执行前置条件，状态信息应当支持快速扫读。
2. 节点的状态、准入、健康度、当前任务和心跳在表格里信息齐全，但视觉优先级不够，普通用户不容易先定位异常节点。
3. 行为门已检查项目 AI 智能体页有注册流程和注册入口，但还没有检查项目节点是否具备图形化管理视图。

## 优化方案

1. 为项目 AI 智能体页增加“列表视图 / 卡片视图”切换，复用组织智能体页已有视图习惯。
2. 卡片视图每张卡展示节点名、状态、准入、健康度、地区、当前任务数、最近心跳和操作按钮。
3. 没有节点时，卡片视图仍显示同一条注册引导，不制造另一套空态文案。
4. 表格视图保持不变，保证高密度审计和复制 ID 场景不丢功能。
5. 行为门新增断言：项目 AI 智能体页必须有列表 / 卡片切换，卡片视图必须显示准入、健康度、当前任务和节点控制操作。
