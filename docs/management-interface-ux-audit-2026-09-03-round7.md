# 管理界面第七轮多角度复验与优化方案（2026-09-03）

## 复验角度

前六轮已经把系统管理、组织管理、项目管理分开，并在项目概览、任务组、执行监控、人工审核、人工指令、系统设置、成员管理、智能体等页面补上总览或处置看板。本轮继续从系统管理员的中文管理路径推演，重点检查“账号与授权”这类高风险页面是否仍然存在“先给操作表单、后给现状列表”的问题。

复验角度包括：

- 高风险管理顺序：账号、授权、服务账号、agent 档案和加入令牌会直接影响系统边界，用户应先看现状，再新增或撤销。
- 中文阅读习惯：系统管理员通常先查“已有谁、给了什么权限、哪些令牌还活着、哪些档案可用”，再决定邀请账号或补授权。
- 操作闭环：看到风险后应能直接跳到对应列表或管理面板，不要求用户记住页面长表顺序。
- 信息完整性：账号邀请、访问授权、系统级项目创建、项目成员授权、智能体入网令牌、agent 档案创建都保留。
- 性能边界：新增看板只聚合本页已经加载的数据，不新增接口、不扩大轮询、不引入新依赖。

## 发现的问题

- 「账号与授权」页已有“账号与授权总览”，但总览后直接进入“邀请账号”“新增访问授权”“创建项目（系统级）”“项目成员授权”等表单；账号列表、访问授权列表、智能体入网令牌和编排智能体档案排在后面。
- 对普通中文管理员来说，这会形成“先填表，后确认现状”的顺序。系统级授权页里这种顺序风险更高：可能重复邀请、重复授权、对错误项目签发加入令牌，或没看到已有服务账号/agent 档案状态。
- 页面没有一张把“待接受邀请、启用账号、系统管理员、服务账号、有效授权、待用加入令牌、启用 agent 档案”组织成可跳转入口的操作看板。

## 优化方案

- 新增“账号与授权操作看板”：用卡片展示待接受邀请、启用账号、系统管理员、服务账号、有效授权、待用加入令牌、启用 agent 档案、可授权项目。
- 看板卡片使用面板跳转，直接定位到“账号列表”“访问授权列表”“智能体入网令牌”“编排智能体档案”等现状区域。
- 调整「账号与授权」页顺序为：账号与授权总览 → 操作看板 → 账号列表 → 访问授权列表 → 智能体入网令牌 → 编排智能体档案 → 邀请账号 → 新增访问授权 → 创建项目（系统级） → 项目成员授权。
- 补充行为门，断言账号与授权页必须先显示操作看板与现状列表，再显示新增操作表单。

## 验收要求

- 桌面页面：账号与授权页先显示总览、操作看板、账号列表和访问授权列表，再显示邀请账号与新增授权表单。
- 移动端页面：390px 宽度下新增操作看板不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、contract:check、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录系统管理页，检查账号与授权页首屏顺序、看板可读性和跳转可用性。

## 实施结果

- 已新增通用跳转卡片 helper，执行监控看板和账号授权看板共用同一份卡片结构，避免同形 UI 重复实现漂移。
- 已新增“账号与授权操作看板”，聚合待接受邀请、启用账号、系统管理员、服务账号、有效授权、入网令牌、启用 agent 档案和可授权项目。
- 已将「账号与授权」页调整为“总览 → 操作看板 → 账号列表 → 访问授权列表 → 智能体入网令牌 → 编排智能体档案 → 邀请账号 → 新增访问授权 → 创建项目（系统级） → 项目成员授权”。
- 已补充行为门断言，确保账号与授权页先展示现状与风险，再展示新增操作表单。
- 已修正旧行为门中按普通字符串切分面板的脆弱断言，改为按真实 `<h2>` 面板标题定位，避免被新看板的跳转属性误伤。
- 已完成快速工程验证：语法检查、diff 卫生、console-behaviour-gate 和 mutation-anchors 通过。
- 已完成真实浏览器桌面复验：账号与授权页面板顺序为“账号与授权总览 → 账号与授权操作看板 → 账号列表 → 访问授权列表 → 智能体入网令牌 → 编排智能体档案 → 邀请账号 → 新增访问授权 → 创建项目（系统级） → 项目成员授权”，页面级横向溢出为 false。
- 已完成真实浏览器交互复验：点击“有效授权”操作卡片后，页面能直接滚动定位到“访问授权列表”，目标标题处于可视区域。
- 已完成真实浏览器窄屏复验：390px 宽度下操作看板保留 6 个入口卡片，首段面板顺序保持为“账号与授权总览 → 账号与授权操作看板 → 账号列表 → 访问授权列表 → 智能体入网令牌”，页面级横向溢出为 false。
