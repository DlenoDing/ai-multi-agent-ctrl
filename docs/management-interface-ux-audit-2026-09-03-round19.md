# 第十九轮管理界面复验与优化方案

## 复验范围

- 系统管理、组织管理、项目管理三层菜单的职责边界。
- 项目 AI 智能体页的节点查看、注册流程、注册脚本来源和远程 MCP 说明。
- 系统“账号与授权”页是否仍把普通项目 Agent 注册操作混在系统管理员界面里。
- 中文用户从“我想注册一台 Agent 机器”到“拿到一次性脚本并确认节点在线”的操作路径。

## 发现的问题

1. 项目级 AI 智能体页已经具备独立菜单、总览、操作看板、Agent 注册流程、节点列表和注册入口，路径正确。
2. 组织级 AI 智能体页已经说明组织页负责全组织节点状态、控制和吊销，项目页负责按项目注册。
3. 系统“账号与授权”页仍有“入网令牌”“编排智能体档案”“项目成员授权”等跨项目能力。功能上这些属于系统管理员的应急、审计和后台代签边界，但当前页没有在首屏明确说明它不是常规项目 Agent 注册入口。
4. 页面副标题仍写“账号邀请、访问授权、项目归属与智能体入网令牌”，容易把 Agent 入网令牌理解为系统账号页的常规操作，而不是跨项目后台能力。
5. “智能体入网令牌”面板没有提醒用户：常规注册必须到目标项目的“项目管理 → AI 智能体 → 注册 agent”完成。

## 优化方案

1. 保留系统管理员的全部现有能力，不删除账号、授权、系统级建项目、项目成员授权、Agent 入网令牌、Agent 档案功能。
2. 在“账号与授权操作看板”后增加“账号与授权职责边界”图形化面板，将页面拆成四类职责：系统账号、授权审计、项目 Agent 注册入口、Agent 档案。
3. 将系统页副标题调整为“系统账号、访问授权、服务账号与跨项目授权边界”，避免把项目 Agent 注册继续放在系统页主语里。
4. 将操作看板里的“入网令牌”卡片改成“跨项目入网令牌”，说明它是系统管理员代签和审计入口。
5. 在“智能体入网令牌”面板顶部增加醒目的边界说明：常规注册进入目标项目的“项目管理 → AI 智能体 → 注册 agent”；系统页只用于跨项目代签、审计和应急处理。
6. 增加行为门：系统账号页必须按“总览 → 操作看板 → 职责边界 → 账号列表 → 访问授权 → 入网令牌”的顺序渲染，并必须出现项目 Agent 注册路径说明。
