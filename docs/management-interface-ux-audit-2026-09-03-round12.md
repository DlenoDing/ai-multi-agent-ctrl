# 管理界面第十二轮多角度复验与优化方案（2026-09-03）

## 复验范围

第十一轮补齐“人工指令”页后，本轮继续从项目执行控制中最容易影响系统走偏的人工裁决链路复验“人工审核”页。该页面承载确认定稿、授权请求、审批请求、发现项处置和历史追溯，属于人侧少数保留入口之一，必须让普通中文用户快速理解“先处理什么、去哪里处理、哪些只是追溯”。

复验角度包括：

- 中文后台习惯：高风险审批页应遵循“总览 → 操作看板 → 当前待办 → 分类明细 → 历史”，避免用户在多张长卡片里寻找重点。
- AI-native 边界：人工审核只处理必须真人裁决的关口，其余执行仍由 AI agent 和总控自动完成；页面要突出“待你处理”和“阻塞执行”的优先级。
- 图形化入口：人工审核总览已有待确认、核心决策、授权请求、审批请求、发现项、涉及任务组、历史等指标，但缺少可点击入口。
- 防跑偏要求：总控或子任务走偏时，人工审核是关键拉回点；界面必须优先暴露阻塞确认、授权/审批、发现项。
- 信息完整性：不减少待你处理、待人工确认、授权与处置、已答历史和最近定稿记录。
- 性能边界：只基于当前已加载的确认单、授权请求、审批请求、发现项和定稿记录聚合，不新增接口、不新增轮询、不引入依赖。

## 发现的问题

- 「人工审核」页当前顺序是“人工审核总览 → 待你处理 → 待人工确认 → 授权与处置 → 已答历史”。顺序比早期清晰，但总览后的数字仍不是可点击入口。
- 用户看到“核心决策”“授权请求”“待处置发现”等风险数字后，不能直接跳到对应明细，只能继续向下读多个大面板。
- “待你处理”是跨可见项目的汇总入口，和当前项目内“待人工确认 / 授权与处置”不是同一个层级，需要一个看板明确区分。
- 与执行监控、人工指令、系统组织等页面相比，人工审核页缺少同形的入口地图，项目控制区的交互一致性不足。

## 优化方案

- 新增“人工审核处置看板”，放在“人工审核总览”之后、“待你处理”之前。
- 看板卡片覆盖：待你处理、待人工确认、核心决策、授权与处置、待处置发现、历史追溯。
- 待你处理卡片跳转到“待你处理”；待人工确认和核心决策卡片跳转到“待人工确认”；授权与处置、待处置发现卡片跳转到“授权与处置”；历史追溯卡片跳转到“已答历史”。
- 看板说明固定处理顺序：先处理待你处理和阻塞确认，再处理授权/审批/发现项，最后查看历史追溯。
- 补充行为门，断言人工审核页必须先显示总览和处置看板，再显示待你处理、待人工确认、授权与处置、已答历史，并断言看板跳转目标存在。

## 验收要求

- 桌面页面：人工审核页先显示人工审核总览、人工审核处置看板，再显示待你处理、待人工确认、授权与处置、已答历史。
- 移动端页面：390px 宽度下新增处置看板不造成页面级横向溢出。
- 工程验证：语法检查、diff 卫生、console-behaviour-gate、mutation-anchors、validate、docker:doctor 通过。
- 运行验证：本地服务启动后用真实浏览器登录人工审核页，检查处置看板可读性、卡片跳转和窄屏表现。
