# 中文管理控制台对象化终态改造

日期：2026-09-06  
状态：完成

## 审计结论

菜单优先改造已经把主要功能从页面内 Tab 提升为稳定入口，但真实多角色走查仍发现四类结构问题。这些问题不影响服务端权限和执行链，却会让普通管理者在登录后难以形成稳定认知。

### 1. 默认组织的初始管理员不成立

系统管理把 `acct_workspace_owner / owner@local` 显示为默认组织的“初始组织管理员”，但该账号实际是 `user_account + workspace_owner`，登录后只能进入项目管理，不能创建组织成员、分配项目／任务组权限或管理组织级 Agent。

这不是文案问题，而是身份数据、运行态迁移和本地初始化凭据三处不一致。终态必须保留两个不同主体：

- 默认组织管理员：`org_admin`，负责组织子账户、项目目录、项目／任务组权限和组织共享 Agent。
- 示例项目负责人：`user_account + project_owner`，只负责有权项目，不自动获得组织治理权。

系统管理员只维护组织启停、配额和初始组织管理员，不直接代管组织子账户。

真实浏览器复验进一步发现，系统管理员登录后仍可切入所有组织的项目管理空间。终态由登录会话显式声明可用控制台范围：系统管理员仅进入系统治理空间；组织管理员和项目成员才进入项目空间。系统级应急 API 权限保留，但不混入日常图形化项目管理入口。

### 2. 项目菜单从“隐藏过深”变成“全部摊开”

项目空间目前一次展开八组、三十多个叶子。每个入口虽然稳定，但侧栏长度超过一屏，用户要在大量同级文字中寻找“注册 Agent”“实时事件”“授权复核”或“仓库凭据”。

终态保留全部稳定叶子和 URL，但桌面按业务分组折叠：当前功能所属组自动展开，其他组只显示组名；点击组名展开，进入叶子后自动切换到对应组。移动端继续使用单一功能选择器，不叠加第二套菜单。

### 3. Agent 的逻辑对象与运行对象仍混淆

“Agent 档案”是总控选角色、模型和 Skill 的逻辑对象；“运行节点”是安装在主机上的执行载体；“注册 Agent”实际签发的是运行节点加入令牌。当前档案列表和创建表单仍放在同一页面，且“注册 Agent”名称容易被理解成创建逻辑 Agent。

终态拆成清晰动作：

- 组织级：共享 Agent 档案、新建共享 Agent 档案、共享运行节点、注册共享运行节点、加入令牌。
- 项目级：Agent 档案、新建 Agent 档案、运行节点、注册运行节点。

档案列表只负责查找和进入详情；创建页面只负责创建。任务组调度候选仍同时包含本项目活动档案和本组织活动共享档案，服务端选择逻辑不变。

### 4. 对象范围没有进入页面名称

从任务组进入监控、任务、审核或指令后，URL 和数据已经带任务组范围，但 H1 仍写“项目监控”“任务”“待我审核”等项目级名称。用户必须再看范围选择器或面包屑才能确认自己是在看整个项目还是一个任务组。

终态页头直接表达范围，例如“任务组监控”“任务组实时事件”“任务组任务”“任务组审核”“任务组指令”；退出任务组范围后恢复项目级名称。列表、菜单和后端 API 不复制第二套实现。

## 交互收敛

1. 系统空间只出现平台运行、组织治理、平台能力和对应说明。
2. 组织空间以成员、项目目录和共享 Agent 为三条主线；成员详情内连续完成账号生命周期、项目角色和任务组角色。
3. 项目空间以项目总览、成员权限、Agent、工作推进、执行观测、人工控制和项目治理分组。
4. 创建项目入口不再常驻每个任务／监控详情页；有 `project:create` 的项目成员可在侧栏项目选择区进入创建。
5. 任务组详情保留对象局部导航，项目全局菜单收敛成分组标题，避免两套完整菜单同时争抢注意力。
6. Agent 列表、创建、运行节点和注册令牌各自只有一个主要对象和一个主要动作。

## 代码边界

`apps/control-plane-ui/public/app.js` 当前仍有 10,611 行。新增能力不得继续以内联模板堆入主文件：

- 菜单分组、折叠渲染和移动选择器归 `modules/navigation.js`。
- Agent 档案列表、创建和详情的纯展示归 `modules/agent-profile-workspace.js`。
- 主文件只保留页面取数、权限上下文、事件绑定和模块组合。

本轮进一步把错误回执解释、任务组执行时间线／监控矩阵、Agent 档案表单、节点卡片、上下文标题和管理空间声明拆为独立模块。主程序不再保存这些模块的第二份实现；契约检查从 `index.html` 的真实加载清单读取消费代码，避免拆分后只扫描 `app.js` 形成假绿。

## 追加实机发现与修正

1. 系统管理员虽有独立系统菜单，仍可切入所有组织的项目空间，系统概览还有“进入项目”旁路。登录响应现显式下发 `consoleScopes`；系统管理员只有系统治理空间，组织管理员拥有组织与项目空间，普通成员只有项目空间。旧书签和手改项目地址会回到系统概览。
2. 仅有项目观察者和单任务组评审权的成员，项目概览仍推荐“生成注册命令”。项目当前主操作现同时按仓库配置权、Agent 管理权和任务组控制权判断，不再推荐必然被服务端拒绝的动作。
3. 任务详情把“过程事件 0 条”和“执行尝试 1 次”混称为记录，视觉上互相矛盾。现分别显示过程事件、本页事件和执行尝试三种计数。
4. Agent 档案创建使用登记值下拉，编辑却允许自由输入。创建和编辑现统一使用执行角色、模型能力和角色 Skill 注册表，并保留当前合法值。
5. 一次性 Agent 安装命令此前只生成节点工作目录内的远程 MCP 配置，默认不合并实际 Codex／Claude／Cursor 客户端；即使首次显式启用，常驻进程也未记住该策略，令牌轮换后停止刷新。安装器现默认且在服务端生成的命令中显式启用远程客户端配置，策略写入节点配置，轮换持续刷新，撤销自动清理；`--no-configure-global-clients` 保留为隔离主机退出开关。复验同时发现 Cursor 从未进入工具探测，已补齐。

## 真实流程证据

- 默认组织管理员在浏览器创建新成员，分别授予项目观察者与单任务组评审角色；新成员以一次性令牌登录后只看到一个项目和获权任务组，创建、Agent 注册与人工指令入口均按权限收起。
- 任务详情真实显示派发尝试、节点、Agent 档案、执行角色、模型与推理、`modelDecision`、会话、最新回送、规则入口和 Git 结果。
- 项目负责人从“注册运行节点”签发一次性命令；远程 Agent e2e 用同形命令真实完成校验下载、注册、自检、中央 MCP 配置、凭据轮换、派发、过程事件、Git 推送、权限恢复、检查点和撤销 ACK。
- 390px 与 1440px 浏览器走查覆盖系统组织、组织 Agent、任务、执行对象、运行节点和任务组监控；页面无横向溢出、重叠或双重移动导航。

## 验收

- 默认组织管理员账号真实登录后进入组织管理，并能创建成员、分配项目／任务组权限和管理共享 Agent。
- 默认组织管理员和示例项目负责人是不同账号，互不借权。
- 桌面项目侧栏首次只展开当前业务组，三十多个叶子不再全部铺开；当前页始终可见。
- Agent 档案列表中不再混入创建表单；“新建档案”和“注册运行节点”不会混淆。
- 任务组范围的任务、监控、审核和指令页从 H1 即可识别范围。
- 系统管理员、组织管理员、项目负责人、评审者在桌面和 390px 下均可完成各自真实流程。
- 全量验证、变异门、Docker、外部只读复审和 Git 推送全部通过。
