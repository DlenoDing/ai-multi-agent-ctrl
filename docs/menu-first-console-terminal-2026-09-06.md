# 菜单优先中文管理控制台终态改造

日期：2026-09-06  
状态：已完成并通过终态复验

## 结论

上一轮已经补齐系统／组织／项目边界、对象详情和真实执行链，但控制台的主要认知模型仍然是“父页面 + 页面内栏目”：项目空间只有九个父菜单，点击后才临时出现三至七个二级栏目；移动端则在内容区出现“当前栏目”选择器。用户必须先记住“注册 Agent 属于项目 Agent 的注册栏目”“质量证据属于执行监控的产出栏目”“任务组权限属于成员权限的任务组栏目”，才能找到操作。

这仍然是 Tab 思维，只是把 Tab 从内容顶部挪到了侧栏。第一阶段先让每个功能拥有稳定页面、明确标题和可复制地址；后续人本化复验进一步确认“稳定页面”不等于“所有入口必须常驻侧栏”。当前终态只把日常查阅与处置放在侧栏，创建、注册和说明由对应对象的主按钮或顶栏问号进入。

## 设计原则

1. **按管理对象和动作命名**：使用“成员账户、权限矩阵、Agent 档案、运行节点、注册运行节点、任务组、新建任务组、任务、新建任务、项目监控、工作会话、Agent 派发、实时事件、质量门禁、待我审核、权限审批、下达指令、指令记录、仓库凭据、系统规则”等直接名称。
2. **列表、创建、详情分开**：列表页用于查找与进入对象；创建入口使用列表页主按钮进入稳定创建地址；详情页只处理当前对象，不把其它列表继续堆在下面。
3. **系统、组织、项目三套菜单彻底分离**：系统管理不出现组织子账户、项目授权、Agent 或执行入口；组织管理不替项目执行；项目管理不出现跨组织治理。
4. **桌面菜单克制，窄屏单一选择器**：桌面侧栏只列日常查阅与处置功能并按业务阶段分组；移动端只显示一个当前位置选择器，不渲染横向滚动菜单和第二层栏目选择器。
5. **原有权限不变**：菜单可见性只能缩小到当前账号可执行或可读取的范围，不能因为重排菜单扩大服务端权限。所有写操作继续由现有 API、状态机、幂等和审计守卫处理。
6. **AI-native 执行不变**：人只创建项目／任务组／任务、管理账号与 Agent、启动／暂停、审核／复核和下达独立指令；任务分析、角色／模型／Skill 选择、派发、执行、回送和结果收口继续由 AI 总控与 Agent Runtime 自动完成。

创建成员、创建项目、新建 Agent、注册节点、新建任务组、新建任务和授予权限仍是独立页面，但只从对应列表主按钮进入。说明页面从顶栏问号进入，不再占据整组侧栏。

## 页面与路由

保留现有服务端页面族和 `?pane=` 兼容编码，但 `pane` 不再作为临时 Tab，而是稳定功能入口的地址组成部分。每个菜单项直接写入对应地址，页面标题使用当前功能名，不再显示父页面名后再补一个重复栏目标题。

对象详情继续使用路径段：

```text
#/system/organizations/:orgId
#/organization/members/:accountId
#/organization/agents/runtime/:nodeId
#/project/:projectId/task-groups/:taskGroupId
#/project/:projectId/tasks/:taskGroupId/:workItemId
#/project/:projectId/agents/:agentId
#/project/:projectId/agents/runtime/:nodeId
#/project/:projectId/monitor/:taskGroupId/session/:sessionId
#/project/:projectId/monitor/:taskGroupId/dispatch/:dispatchId
```

## 页面结构

- 页头：当前具体功能名称、简短职责说明、账号和刷新。
- 层级路径：组织／项目／任务组／任务／执行对象。
- 内容首段：当前对象、状态、关键指标和唯一主要动作。
- 列表：紧凑、可筛选、按更新时间或创建时间倒序；名称直接进入详情。
- 创建：字段按中文业务顺序排列，提交后直接进入新对象详情。
- 详情：纵向信息带，固定返回上级；复杂协议字段按需展开。
- 空态：解释为什么为空并提供唯一下一步，不重复整套流程说明。

## 复验与互审

### 第一轮外部审查

独立只读审查发现五项问题，均已复现和修复：

1. 当前叶子菜单因同目标早退而保留旧任务组范围。
2. 任务组任务列表的分页游标泄漏到项目级任务列表。
3. 待办红点与处置按钮只按父页面聚合，不能区分待我审核、授权复核、产出验收、阻塞与门禁和指令记录。
4. 十四个说明 workspace 在删除旧 Tab 后失去生产入口。
5. 功能看板跨叶子跳转使用 `replaceState`，浏览器后退跳过来源功能。

对应修复提交：`4bd91d4`、`3588190`、`56db2b3`。测试强化提交：`162aade`。

### 第二轮外部审查

复审确认第一轮问题主路径已闭合，未发现 P0/P1；另发现项目首页“当前下一步”仍按父页面进入审核或监控。终态实现按待办类型选择精确叶子：定稿进入待我审核，授权／审批／发现进入授权复核，混合待办进入待办汇总，质量门进入产出验收，其它执行阻塞进入阻塞与门禁。对应修复提交：`8468f29`。

## 验收标准

- 新登录用户不需要知道父页面和栏目关系，即可从日常菜单或对应对象主按钮找到创建项目、成员授权、任务组权限、Agent 档案、注册节点、新建任务、启动、监控、审核、复核、指令和仓库配置。
- 桌面侧栏没有“选中父菜单后才出现”的临时栏目；内容区没有承担主要导航职责的 Tab。
- 移动端只有一个功能选择器，不存在横向功能菜单叠加栏目选择器。
- 页面 H1 与实际功能一致，例如打开节点列表时是“运行节点”，而不是先写“项目 Agent”再写“项目运行节点”。
- 深链接、刷新、前进／后退和跨账号重新鉴权保持正确；无权菜单和写操作不出现。
- 不删除已有信息与能力，所有对象详情、实时事件、控制 ACK、Skill／规则、Git 证据和审核记录继续可达。
