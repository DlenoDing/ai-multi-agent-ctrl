# 管理界面与交互复验审计 Round 44

审计时间：2026-09-04 17:00 +08

## 审计范围

- 重新核对系统管理、组织管理、项目管理是否已经分层清楚。
- 重点复验项目「AI 智能体」页是否能让普通中文用户快速找到 agent 查看、注册、注册脚本、自检确认、远程 MCP/Skill 生效和实时回送入口。
- 从“第一次接入 agent”的真实操作路径推演：进入项目后先看什么、点哪里生成脚本、脚本执行后在哪里确认上线、异常时去哪里看实时事件。
- 确认本轮优化不丢失现有功能，不改变服务端集中 MCP、agent 端只运行 Runtime、一次性 join token 项目绑定、节点实时回送这些核心设计。

## 复验结论

前序版本已经完成了核心系统设计与多数管理页面拆分：

- 系统管理只承载全局账号、服务账号、访问授权、系统运行、模型能力、技能源、系统规则和跨项目审计。
- 组织管理承载组织成员、组织项目、组织范围 agent 节点治理和加入令牌审计。
- 项目管理承载项目成员权限、项目 AI 智能体、任务组、执行监控、人工审核、人工指令和项目设置。
- 项目「AI 智能体」页已经有总览、操作看板、注册流程、运行闭环、节点处置流程、节点列表、卡片视图和注册表单。

本轮继续按普通中文用户的阅读和管理习惯复验，发现项目「AI 智能体」页仍有一个信息架构问题。

### P1：注册脚本入口需要更靠前、更像操作台

现象：

- 页面顶部有“注册新 agent”卡片可以跳到“注册 agent”表单。
- 页面中段已有“Agent 注册流程”和“Agent 接入与运行闭环”。
- 但真正的“注册 agent”表单仍在“项目智能体节点”之后。
- 当节点列表变长时，用户会先读到节点治理内容，再滚动很久才看到生成 join token 和安装脚本的表单。

影响：

- 对第一次接入 agent 的用户来说，“注册脚本哪里来”仍不够直观。
- 用户容易误以为节点列表或组织 agent 页能直接拿到注册脚本。
- 当前页面虽然功能齐全，但缺少一个把“签发 token、复制脚本、等待自检、看实时回送”串在一起的短操作台。

处理方案：

- 在项目「AI 智能体」页的注册流程之后、运行闭环和节点长表之前新增“注册与脚本操作台”。
- 操作台用四个图形化操作卡串联：
  - 签发 join token。
  - 获取服务端生成的 sh 安装命令。
  - 等待节点自检并查看节点列表。
  - 到执行监控查看实时回送、派发状态和控制 ACK。
- 操作台必须明确：
  - 注册脚本不是固定写死命令。
  - 必须先由服务端按当前项目签发一次性 join token。
  - 安装命令和明文 token 只在签发成功弹窗显示一次。
  - agent 端只运行 Runtime，后续通过服务端 Gateway、远程 MCP 和最小 Skill 工作集执行任务。
- 保留现有节点列表、卡片视图、节点控制、注册表单、令牌审计和后端协议。

### P2：行为门应覆盖这个关键入口

现有行为门已经覆盖项目 AI 智能体页的大部分结构，但没有单独要求“注册脚本操作台”必须位于节点长表之前。本轮需要补充断言：

- 项目 AI 智能体页必须出现“注册与脚本操作台”。
- 操作台必须位于“Agent 注册流程”之后、“Agent 接入与运行闭环”和“项目智能体节点”之前。
- 操作台必须提供跳转到“注册 agent”、“项目智能体节点”和“执行监控”的入口。
- 操作台必须说明服务端生成脚本、一次性 token、只显示一次、agent 端只运行 Runtime、远程 MCP/Skill 由服务端集中支持。

### P3：稳定性与性能判断

本轮优化属于低风险前端信息架构增强：

- 不改数据库结构。
- 不改 API。
- 不改权限模型。
- 不改 agent 注册协议。
- 不新增轮询或网络请求。
- 不引入大组件或依赖。

因此不会增加服务端压力，也不会影响高并发执行链路。它只减少用户寻找入口的时间，并降低误操作概率。
